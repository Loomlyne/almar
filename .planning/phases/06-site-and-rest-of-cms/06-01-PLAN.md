## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| build (anon key) → `api_*` views | public read of content; must never reach requests, bookings, settings, saved stays, locks or drafts |
| public Worker `almar` → `submit_site_request` / `book_consultation` (service role) | every guest field untrusted; spam and slot races |
| signed-in guest → `saved_stays` (authenticated role, RLS) | one user must never see or change another's rows |
| owner browser → `/api/ops/*` save endpoints | `locked_fields` and every new body key untrusted |
| controller terminal → `import_site_content` | one-time import on live data |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-01 | Info disclosure | new tables via anon | mitigate | RLS on every table, `revoke all` then column grants and parent-following policies; views select explicit columns; pgTAP asserts anon sees nothing of requests, consult_*, saved_stays, locked_fields |
| T-06-02 | Tampering / Spoofing | `site_requests` writes | mitigate | no anon or authenticated insert; only `submit_site_request` / `book_consultation`, executable by service_role; payload checked per kind by `site_request_payload_ok` in a table check; a package request needs a published tier slug (checked inside `submit_site_request`); honeypot and `lib/form-rate-limit.ts` at the route (06-05) |
