# 02-24 — Continue page: the sign-in link no longer signs in on a GET

Job 02, 2026-10-05. Review finding 3 (scanners burn links; login CSRF). Design signed by the owner
(`02-JOB02-DECISIONS.md`); the draft is `app/auth/confirm/continue-screen.tsx` with harness scene
`tests/journey/scenes/auth-continue.tsx` (`/__harness?c=auth-continue&s=draft&l=en`).

## Tasks

1. Link. `lib/auth/send-link.ts` / `magic-link-server.ts`: the confirm URL carries `token_hash`, `type`,
   `m` = masked email (first character, `•••`, `@` and the domain; e.g. `l•••@gmail.com`) and `s` =
   base64url HMAC-SHA256 over `"almar-continue-v1\n" + token_hash + "\n" + m`, keyed with
   `SUPABASE_SERVICE_ROLE_KEY` (server-only; no new secret). Pure helpers `maskEmail`, `signContinue`,
   `verifyContinue` (constant-time compare) in `lib/auth/continue.ts`, node-tested.
2. Page. `app/auth/confirm/route.ts` becomes `app/auth/confirm/page.tsx` (force-dynamic): reads the query,
   never verifies on GET. Renders `ContinueScreen` with the masked email only when `verifyContinue` passes;
   otherwise the line without the email ("Continue to sign in to ALMAR."). Missing `token_hash`/`type`, or a
   type outside the allowed three → redirect to `/login?expired=1` (`/sign-in?expired=1` on the ops host).
   Response metadata: `robots noindex`; `referrer: "no-referrer"`.
3. Action. `app/auth/confirm/actions.ts` `"use server"` `confirmSignIn(form)`: `verifyOtp` with the posted
   `token_hash` and `type` (same allow-list), then the existing return-cookie redirect (303 semantics via
   `redirect`); on error the expired redirect. Next's server-action origin check covers the POST.
4. Copy. Draft strings move to `lib/copy/guest.ts` under `auth.continue` (EN/AR/ES as drawn, plus the
   no-email line: EN "Continue to sign in to ALMAR." AR "تابع لتسجيل الدخول إلى ALMAR." ES "Continúa para
   iniciar sesión en ALMAR."). Additions only (shared file, controller asked).
5. The draft becomes the screen: form posts `confirmSignIn` with hidden `token_hash` and `type`; busy state on
   the button; "Not you?" links to `/login` (ops: `/sign-in`). The split layout is shared with
   `SignInScreen` through one extracted frame component, not copied.
6. Tests: node (`continue` helpers, page never calls verifyOtp on GET — source assertion), Playwright spec on
   the harness scene at 390/834/1440 EN/AR (RTL, the email in LTR `bdi`), and the auth-magic-link test for the
   new URL parameters.

## Done when

Opening the link changes nothing until Continue is pressed; a forged `m` shows no email; the old one-click
path is gone.
