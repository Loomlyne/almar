## Names taken from 3.2 (reconciled against 03.2-API-CONTRACT.md, 2026-10-05)

Every 3.2 name this plan uses is listed in the interfaces block above, copied from the contract. Task 1 step 1 greps
each in 3.2's merged migration; a difference is fixed here (3.2 wins) and listed in the SUMMARY. Two deliberate
choices against the contract's wording, for the lead:

1. **`api_stay_blocked_days`** gains permanent nights (paid, confirmed, completed) and hand-made holds
   (`awaiting_payment`), but **not** 30-minute web holds: the view is read at build time, so a web hold would stay
   baked as "unavailable" until the next Publish, long after it freed up. The live quote reports web holds as
   `sold_out`. This is now written into `03.2-API-CONTRACT.md` §2.2 (edited by the planner, 2026-10-05). The anon view reads them through a definer function `public_booked_nights()` so no booking table is
   granted to anon.
2. **`ops_add_block`** is replaced with the same signature and result; the only changes are the per-stay advisory lock
   for scope `stay` and `overlapping_bookings` counted from `booking_nights` (permanent rows and live holds). Also in
   the contract's §2.3 now.
