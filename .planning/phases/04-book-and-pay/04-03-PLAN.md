## Phase Goal

ROADMAP Phase 4 (`**Mode:** mvp`), quoted as written: "A guest can request a real one-destination trip (stay +
add-ons), pay it by bank transfer, and the owner records the payment in the dashboard. No card provider is needed."

languages, sees the server's prices and every refusal as a reason, enters who is travelling, chooses deposit or full and
the UAE airport, accepts the terms, holds the dates for 30 minutes and reaches an enabled "Send request". 04-06 makes
that button send.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| URL query -> page | anyone can craft `/booking/trip?…` |
| sessionStorage -> page | the guest, an extension or another script on the origin can edit the stored trip |
| page -> `/api/booking/quote`, `/hold`, `/release` on `almar` | the server re-validates and re-prices everything (04-02, 04-08); the browser's numbers are never read |
| page -> wa.me | a message the guest sends from their own WhatsApp |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-03-01 | Tampering | amounts on the page | mitigate | display only: every amount is a quote or hold field through `formatAed`; the hold body carries no price (node parity with `parseHoldRequest`, which refuses unknown keys); the server re-prices at hold time; grep gate on `* 100`, `/ 100`, `toFixed`, `Math.round`, `parseFloat` in app/booking and the step components |
| T-04-03-02 | Tampering | crafted query or stored state | mitigate | `parseTripQuery` and `readTripState` accept only the exact shape (keys, slug, ISO dates, counts, uuid ids, ref and token shapes) and return null otherwise, never repaired; offer names and stay titles are rendered as React text, never as HTML |
| T-04-03-03 | Information disclosure | link token and hold ref in sessionStorage | accept | tab-scoped, same-origin storage only; never in a URL, `href`, WhatsApp text or log (grep acceptance in Task 4); the token opens only this guest's own booking (04-08 access rule); cleared when the hold ends or is released |
| T-04-03-04 | Information disclosure | contact and traveller details in sessionStorage | accept | needed so a language switch or a reload keeps what the guest typed; sessionStorage (closes with the tab), never localStorage, never logged; no amount and no terms flag stored |
| T-04-03-05 | Spoofing | cross-site POST to the booking routes | mitigate | the server checks the exact Origin (`isAllowedPostOrigin`); the page sends same-origin `fetch` with JSON and `referrer: same-origin`, so its Origin is real (F-02), proven by the built-Worker browser test in Task 5 (never 403) |
| T-04-03-06 | Repudiation | terms acceptance | mitigate | `termsAccepted: true` is sent only when the box is ticked in this hold (not restored from storage); the server stores the terms version and time (04-02) |
| T-04-03-07 | Denial of service | quote storm, double hold | mitigate | quotes debounced 300 ms with the previous request aborted; Hold disabled while in flight (one request per click, tested); no automatic re-hold (Q-08); the server limiter (5 per email, 20 per IP per hour) stays the guard |
| T-04-03-08 | Information disclosure | stay data and prices reaching the stay page's client props | mitigate | StayBooking gets the slug and strings only (job 11's rule); the trip page gets prices only from the quote over HTTP |
| T-04-03-09 | Spoofing | WhatsApp second-city message | mitigate | built by `secondCityHref` from the title, destination, dates and the reference only; no amount, no token (node test) |
| T-04-03-10 | Information disclosure | trip pages in search results | mitigate | `noindex, nofollow` meta, out of the sitemap (`isSitemapExcluded`), no token in any URL the page builds |
| T-04-03-SC | Tampering | package installs | accept | no package is added (no install task; `package.json` and the lockfile are not touched) |
