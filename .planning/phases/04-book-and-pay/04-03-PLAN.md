## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| URL query -> page | anyone can craft `/booking/trip?…` |
| sessionStorage -> page | the guest, an extension or another script on the origin can edit the stored trip |
| page -> `/api/booking/quote`, `/hold`, `/release` on `almar` | the server re-validates and re-prices everything (04-02, 04-08); the browser's numbers are never read |
| page -> wa.me | a message the guest sends from their own WhatsApp |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-03-01 | Tampering | amounts on the page | mitigate | display only: every amount is a quote or hold field through `formatAed`; the hold body carries no price (node parity with `parseHoldRequest`, which refuses unknown keys); the server re-prices at hold time; grep gate on `* 100`, `/ 100`, `toFixed`, `Math.round`, `parseFloat` in app/booking and the step components |
| T-04-03-02 | Tampering | crafted query or stored state | mitigate | `parseTripQuery` and `readTripState` accept only the exact shape (keys, slug, ISO dates, counts, uuid ids, ref and token shapes) and return null otherwise, never repaired; offer names and stay titles are rendered as React text, never as HTML |
| T-04-03-03 | Information disclosure | link token and hold ref in sessionStorage | accept | tab-scoped, same-origin storage only; never in a URL, `href`, WhatsApp text or log this plan builds (grep acceptance in Task 4); 04-06 adds the one same-origin booking-page href on the sent state (P6-14, Q-07); the token opens only this guest's own booking (04-08 access rule); cleared when the hold ends or is released |
| T-04-03-04 | Information disclosure | contact and traveller details in sessionStorage | accept | needed so a language switch or a reload keeps what the guest typed; sessionStorage (closes with the tab), never localStorage, never logged; no amount and no terms flag stored |
