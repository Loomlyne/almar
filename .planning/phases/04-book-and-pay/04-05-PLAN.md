## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| email link → booking page | The link carries a capability token |
| browser → /api/booking/view | Untrusted ref and token |
| our data → email HTML | Guest-entered text inside HTML |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-05-01 | Information disclosure | booking by ref guessing | mitigate | View needs the HMAC token (link_version) or the signed-in email; unknown and refused give the same 404 |
| T-04-05-02 | Information disclosure | stay access before confirmation | mitigate | `stay_access` read only for confirmed/completed, in the server; never in the build or a public view (C-14) |
| T-04-05-03 | Information disclosure | token leaking via Referer | mitigate | `referrer: no-referrer` on the page; the token never appears in links the page renders |
| T-04-05-04 | Information disclosure | private fields in the view | mitigate | View omits email, phone, emergency contact, payment and session ids; test asserts the key list |
| T-04-05-05 | Tampering | HTML injection in emails | mitigate | Every value escaped; hrefs checked absolute https; test with markup in a name |
