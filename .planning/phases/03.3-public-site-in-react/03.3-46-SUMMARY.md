  and date changes; Clear filters resets all five.

  `blocked_dates`. No copy file touched.

## Deviations from Plan

**1. [Rule 3 - Blocking] Minimal stay-browser edit inside Task 1.** Removing `Carry` from `filter-state.ts` broke
`stay-browser.tsx` (tsc), so the browser's carry state was replaced by the state's own dates in the Task 1 commit; the
Dates control itself is Task 2. `stateFromQuery` returns `{ state }` (not `{ state, carry }`), which keeps every existing
`.state` read in the tests valid.

**2. [Test scope] Tests 7 and 11 also updated.** Test 11's Tab order gained the Dates trigger stop; test 7 checks the
Dates trigger is back to "Add dates" after Clear. Test 12's names check is extended after the main assertions with the
range-set trigger and the x button.

**3. Clock.** Tests that touch dates use `page.clock.setFixedTime("2026-10-04T09:00:00+04:00")` (timers keep running)
rather than `clock.install`, as the stay-detail specs do.

**4. Popover width.** Arbitrary Tailwind values are forbidden by the token test, so the one-month panel is `w-menu` with
`maxWidth: var(--radix-popover-content-available-width)` as an inline style.

The light footer from plan 41 did not break any assertion in this spec; nothing in the private-stays spec needed the
footer fix the lead anticipated.
