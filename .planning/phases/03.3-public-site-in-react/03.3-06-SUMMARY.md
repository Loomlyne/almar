## Deviations

1. **No own `playwright.build.config.ts`; the proof is not under local wrangler.** The plan's own runner is dropped
   by R-4. Plan 03's `playwright.build.config.ts` serves the assembled `out/` with `wrangler dev`; you said no
   wrangler, so I did not run it. The same specs ran on a production `next start` (above) and on `next dev`. For the
   controller: `node scripts/assemble-cloudflare.mjs`, then
   `PW_PORT=<free> npx playwright test -c playwright.build.config.ts tests/build/stay-detail --workers=1`. The specs
   use only relative URLs and `localePath`.
2. **`PublicFrame` is not used; the page has `components/pages/stay-detail/chrome.tsx`.** `PublicFrame` (plan 03)
   renders `<WhatsApp />` with no way to pass a class, `tests/public-frame.test.mjs` asserts exactly one bare
   `<WhatsApp />`, and the file is not mine, so the float could not be lifted above the dock through it. `chrome.tsx`
   is the same chrome with `<WhatsApp className="bottom-dock mb-4" />`. Proposed follow-up: a `whatsappClassName`
   prop on `PublicFrame`, then `chrome.tsx` goes.
3. **`SiteNav tone="on-image"` is broken (plan 02, `components/ui/nav.tsx`).** The cva base has `sticky`, the variant
   has `absolute`, both are emitted, `sticky` wins: the header takes 61px of the page and shows ivory on ivory above
   the hero. Measured in the browser. I wrap it in an `absolute inset-x-0 top-0` div inside `chrome.tsx`. The fix is one
   line in `nav.tsx` (merge the class string with `cn()`). Plan 04's home page uses the same tone and will hit it.
4. **`PublicFrame` default `homeHref` is wrong.** With `localeHrefs` from `currentPath` the default is
   `hrefs[locale]`, which is the page's own URL, not the locale home. Plans 04 and 05 must pass `homeHref`. Its
   phone text is `+971563883302` where design 4.1 row 28 prints `+971 56 388 3302`; `chrome.tsx` imports the same
   constant so one fix serves all pages.
5. **The locked Destination segment is focusable.** Plan 02's `JourneySegment` renders it as an `aria-disabled`
   `<button>`. The plan says "neither is in the Tab order". The Stay segment is not focusable (`tabIndex -1`). The
   spec asserts what is true: Destination is `aria-disabled`, has no popup, opens nothing on click or Enter; Tab from it
   lands on Dates.
6. **Two plan sentences differ from plan 02's components.** Back from When on the phone sheet closes the sheet (the
   destination is locked, so there is no Where step to go back to); Done in the bar's Dates panel moves to the Guests
   panel, it does not close. The spec asserts both as built.
7. **The hide-rule check.** The plan says zero `framer-1sl02v6` under `app/`. That class is also in the own CSS of 12
   other Framer pages (destinations, contact, services, blog, ...), so the check is on the rule job 05 added,
   `#about .framer-1sl02v6`. It is 0.
8. **"Disabled stand-in" rule has two named exceptions.** The locked Destination segment (a lock, by design) and
   anything inside the Dates and Guests panels (past and blocked days, the first month's Previous, a stepper at its
   floor). Everything else disabled or `aria-disabled` fails the spec.
9. **No journey-store provider exists on this branch** (plan 04's `JourneyChoiceProvider` is in another worktree).
   `booking.tsx` reads and writes `sessionStorage` itself with the pure functions of `lib/journey-choice.ts`. On this
   page the destination id is the stay's destination slug; plan 04's home bar may use another id, which only matters
   for a destination filter, never for the stay page (it always forces its own).
10. **Hero composition is my reading of board 5i.** The board's images are not in the repo. Bar near the top under
    the header (so the calendar opens over the photo), destination, h1 and tagline at the bottom clear of the dock,
    one screen tall capped at 900px. Because the bar sits on the photo, the sample-dates note is ivory, not muted as the
    plan says (muted grey on a dark scrim is unreadable).
11. **Footer wording and the dock comma are drafts.** `lib/copy/stay-detail.ts` also holds the footer's "opens in a new
    tab", language-row name and copyright line (EN is the live footer's line); `PublicFrame` callers need them and no
    copy file had them. The dock's line 1 uses an Arabic comma in AR.
12. **Task 5's byte block went into Task 3's commit** (`built-documents.test.mjs` was written once, with both).
13. Counts: each stay lists **3 experiences and 3 services** (7 experiences exist across the 12). The page renders what
    `getCatalogForStay` returns; the spec reads the counts from it.
