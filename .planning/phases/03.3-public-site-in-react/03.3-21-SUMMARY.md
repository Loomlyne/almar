## What was built

**`components/ui/scroll-collage.tsx`** - `ScrollCollage({ images: { src; alt }[]; children; className? })`, `ScrollCollageImage`.
- Root `<div data-scroll-collage class="relative h-375 md:h-575">` (1500 px, 2300 px from 48rem). The caller's statement sits in a sticky wrapper (`top-21/50` = 42 % of the screen, `max-w-100` = 400 px, centred, above the photos).
- Five photos (a sixth image is ignored; no images render nothing), `aspect-5/6`, 170 px wide (300 px from md), slots as whole class names with Tailwind fractions and logical `start-`/`end-` (so Arabic mirrors): tops 8/35/57/77/87 % below md, 5/30/48/65/78 % from md; offsets end 6 %, start 0, end 0, start 3 %, end 6 %.
- A13: each photo carries `data-scroll="drop"`, the hook `HomeWelcome` uses for A9. `MotionController` (job 11) writes the inline `translate` from the scroll (`dropOffset`, same formula, easing and distance as A9), only when the boot script set `data-motion="on"` (never under reduced motion). The server markup carries no hidden class and no inline style: with JavaScript off every photo stands in its place.
- Below md `max-md:translate-none!` outranks the engine's inline offset, so the photos stand still on a phone. This is the one place this plan differs in method from A9: `HomeWelcome`'s photos are not drawn on a phone at all; the collage draws them (170 px), so it needs the override. The engine and `lib/motion.ts` are untouched.
- Nothing inside is focusable, no link, button, role or dialog; each `<img>` keeps the alt it is given.

**`components/ui/media-row.tsx`** - `MediaRow({ title: string; body: ReactNode; image: { src; alt }; className? })`, `MediaRowProps`. Server component. One column below md (text, then photo), two equal columns from md (`md:grid-cols-2`), text block `max-w-90` (360 px) at the inline start, photo `aspect-3/2`, `max-w-120` (480 px), `md:justify-self-end`. Title is a `<span class="font-display text-heading text-teal">` (**the element and classes `MediaCard` renders for its own title**, S3-26 point 2: 24 px on a phone, 32 px from md); body `<p class="m-0 text-body text-ink">`. No reveal inside: the caller wraps it in `Reveal kind="row"` (A7), as job 11's rows do.

**Harness scene `scroll-collage`** mounts `MotionController` itself (the harness has no `PublicFrame`) and an `EngineOn` sibling that puts `data-motion="on"` back before the controller's effect when reduced motion is off: the root layout's boot script turns the flag off after 3 s if the controller is not ready, and the dev server can take longer than that to compile the scene. This is scene-only; the page path is the real boot script plus `PublicFrame`, and plan 25 proves it on the built page. **Scene `media-row`** is one `row` state. Neither scene name is in `tests/journey/matrix.ts`, so there is no screenshot baseline.

## Deviations from Plan

**1. [Rule 1 - Bug in the plan's text] A13's "transform" is the `translate` property.** Job 11's engine writes `el.style.translate`, not `transform`. The spec checks both (`atRest`: `translate` zero or `none`, and `transform` `none` or the identity matrix) and measures the drift through `translate`. Behaviour as the plan describes.

**2. [Rule 3 - Blocking] Below-md stillness by CSS, not by the engine.** The engine applies `data-scroll="drop"` at every width, and `HomeWelcome` avoids it only by not drawing the photos below md. The collage draws them, so `max-md:translate-none!` is on the photos (the plan said "below that breakpoint the photos stand in their final place"; `components/site/motion-controller.tsx` is a shared file and was not edited).

**3. [Rule 3 - Blocking] `px-4` on the held statement (not 20 px) and `md:gap-16` on `MediaRow` (not 80 px).** `tests/design-tokens.test.mjs` allows spacing steps 0, 0.5, 1, 2, 3, 4, 6, 8, 12, 16 only; `px-5` and `gap-20` failed it. The statement is 368 px of text inside the 400 px box, the row gap is 64 px (the picture draws 80). Owner's call if 80 matters: it needs a token step or an allowance in the controller-gated test.

**4. [Scope] Step 0 `merge-base` check and the `origin/main` merge** - see Step 0. Neither blocked the plan.

**5. [Scope] G1 closed, no edit.** The plan makes G1 open "when job 11's story card has no body slot". `MediaCard` has the `detail` slot (job 11's own stay and home cards put their text there) and takes `ratio`, so the plan's G1 edit (a `body` prop on `card.tsx`) was not made.
