## Deviations

1. **[R-3 fallback, needs the controller] The home does not render `PublicFrame`.** It takes no page-supplied nav, and its
   `currency` prop is a boolean that leaves SiteNav uncontrolled (starting at AED), so owner answer 1 and R-8 ("choosing AED first is a
   real change") cannot be met through it. `components/pages/home/home-nav.tsx` renders the same SiteNav, SiteFooter and WhatsApp with
   the same held controls off (`login={false}`, no cart, `newsletter={false}`, no List with us) and takes the contact details from
   `PublicFrame`'s own `SITE_CONTACT`. Proposed follow-up, a few lines in plan 03's file: let `PublicFrame` accept a controlled
   `currency` (`{ selected, onChange }`); then `HomeFrame` can go. The language names row is duplicated in `home-nav.tsx` (three
   constants) for the same reason.
2. **[Found in plan 02's file, worked around, needs the controller] `SiteNav tone="on-image"` is `sticky`, not `absolute`.** The
   `cva` base lists `sticky` and the tone lists `absolute` in one class string; the stylesheet lets `sticky` win. Measured on the
   build: `position: sticky`, 61 px in the flow above the hero, transparent, with the white wordmark on the ivory page. I did not
   touch `components/ui/nav.tsx`; `HomeNav` puts the over-the-hero bar in an `absolute inset-x-0 top-0 z-40` wrapper. Plan 06 (stay hero,
   `tone="on-image"`) will hit the same thing. The right fix is `cn(...)` or dropping `sticky` for that tone in `nav.tsx`.
3. **[Money review not done by a fresh agent] This executor has no sub-agent tool.** The Task 2 diff is 20 added lines in
   `rewriteHomeAmounts` and nothing else in the file (`git diff --stat lib/fx/rates.ts`: 1 file, 20 insertions). The controller needs to
   have a fresh Opus reviewer read `git diff 4969f63..8e813f7 -- lib/fx/rates.ts` before the hand-over (00-common-rules.md).
   What I checked myself: the regex needs `AED `, a digit group, the published en dash, a second digit group and an optional `+`;
   an end that cannot convert (zero or non-finite rate) leaves the whole range as written, never NaN; choosing AED returns the same
   text; the pass is idempotent with the single-amount rows after it; decimals, grouping and the parser are untouched.
   `homePriceScript()` (dead code, imported by nothing) still carries the old per-source logic and was left alone, as the plan says.
   Measured, rates `{aed 3.6725, eur 0.92}`: `From USD 3,000/person · Est. USD 21,783.53–24,506.47`,
   `Est. EUR 20,040.84–22,545.95`, Sovereign `Est. USD 54,458.82–68,073.52+`.
4. **[R-4] No `tests/build/home/playwright.build.config.ts`.** The build spec runs under plan 03's `playwright.build.config.ts`
   (local wrangler over the assembled `out/`). The plan's last acceptance line, that the default dev-server suite also runs the home
