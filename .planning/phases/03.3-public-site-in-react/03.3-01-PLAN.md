Node tests and imports (measured 2026-10-03): every existing node test imports only leaf `.ts` files
("No imports so Node tests load it directly", lib/journey-format.ts). A lib/data module that imports
`./resolve` without an extension cannot be loaded by `node --test`, and adding `.ts` extensions would need
`allowImportingTsExtensions` in tsconfig.json (a config change this plan does not make). Therefore:
tests/helpers/load-ts.mjs bundles the module with esbuild (already a devDependency, 0.25.4):
`build({ entryPoints:[abs], bundle:true, platform:"node", format:"esm", write:false, packages:"external" })`,
writes the output to a temp `.mjs` under os.tmpdir() and returns `import(fileUrl)`. Fixture reads use
`process.cwd()`, so tests run from the repo root as they already do. `node --test tests/*.test.mjs` does not
pick up `tests/helpers/*.mjs` (the glob needs `.test.mjs`).
