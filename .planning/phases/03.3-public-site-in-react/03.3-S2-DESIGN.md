### 2.2 Six extensions and two new primitives

1. **`MediaCard` button form** (`card.tsx`). `onOpen?: () => void` renders the stretched hit area as a
   `<button aria-haspopup="dialog">` in place of the stretched `<a>`, and forwards a ref so focus can come
   back. Today it has `href`, `action`, or neither (`card.tsx:46-81`). Dashboard use: catalogue thumbnails that
   open the side panel (D-88).
2. **`Dialog size="detail"`** (`dialog.tsx`). A 760px (`max-w-calendar`, 760, already a token) centred panel
   from `md` up, full screen below. A media slot above the body, the close square over the media, a
   scrolling body, and a `footer` docked at the bottom. It keeps `z-70`, the `bg-ink/40` scrim and the
   focus trap that `tests/overlays.test.mjs` pins. Dashboard use: the 7i side-panel preview.
3. **`ChipGroup orientation="vertical"`** (`chip-group.tsx`): 5e's stacked full-width Type buttons. Same
   semantics (single select, `aria-pressed`), so the desktop and phone forms are one component.
4. **`Chip onRemove`** (`chip.tsx`): 5e's removable filter chip. Teal-tint ground, ×, `aria-label`
   `Remove filter: Cartagena`. The teal tint is a section or panel ground, never text, which holds here.
5. **`components/ui/checkbox-group.tsx` — `CheckboxGroup`** (new). A `<fieldset>` with a `<legend>` (12px
   uppercase muted, `ar:normal-case`) over `Checkbox` rows of `min-h-11`. Multi-select. No radio controls,
   so it suits the standing rule. Dashboard use: 7i filters, 7h connections.
6. **`components/ui/count-badge.tsx` — `CountBadge`** (new). 20px square, teal ground, ivory 12px,
   `tabular-nums`, inside a `<bdi>`. On the Filters button now, and the cart's badge later (D-66).
7. **`SiteNav` current page in AR and ES** (`nav.tsx:250` or `public-frame.tsx`). It compares `href` with an
   **English** `currentPath`, so on `/ar/experiences` nothing is marked current. The fix compares
   `stripLocale(href)`. Found by reading the code, not run.
8. **`components/pages/experiences/`** (page parts, not primitives): `catalog-browser.tsx` (client state
   owner, the counterpart of `stay-browser.tsx`), `catalog-filters.tsx` (controlled), `item-overlay.tsx`,
   `filter-state.ts` (pure).

### 5.2 `public/_redirects` (question 6.1 answer A)

Checked against Cloudflare's own documentation for Workers static assets
(`developers.cloudflare.com/workers/static-assets/redirects/`, updated 25 Aug 2026):

- The file is read from the asset directory and is not served itself.
- 301 is supported.
- The destination may carry a query string.
- Matching on the source query is not supported, and none is needed here.
- The limit is 2,000 static and 100 dynamic rules; this file needs 9.
- Redirects run before asset matching and before `_headers`.
- No Worker script runs on `almar` (no `main`), so nothing bypasses the file.

```
# /services and its detail pages were folded into /experiences (D-64, D-67; owner, 2026-10-0x)
/services                                   /experiences?type=service                                     301
/services/                                  /experiences?type=service                                     301
/services/24-7-private-concierge            /experiences?type=service&item=24-7-private-concierge          301
/services/24-7-private-concierge/           /experiences?type=service&item=24-7-private-concierge          301
/services/luxury-ground-transport           /experiences?type=service&item=luxury-ground-transport         301
/services/luxury-ground-transport/          /experiences?type=service&item=luxury-ground-transport         301
/services/vip-airport-meet-greet            /experiences?type=service&item=vip-airport-meet-greet          301
/services/vip-airport-meet-greet/           /experiences?type=service&item=vip-airport-meet-greet          301
/services/*                                 /experiences?type=service                                     301
```

The last rule also catches the seven `/services/<slug>` links that answer 404 today. Each trailing-slash
form is listed explicitly because the docs do not say whether a source matches both forms. `/ar/services`
and `/es/services` never existed, so they get no rule.

**Not verifiable here:** a session never runs wrangler, so the redirects are proven by a test over
`out/_redirects` (the lines exist, are well-formed, every destination resolves to a React document, and
there are no loops), then live on `preview.almarprivatejourney.com` in the owner's test steps.
