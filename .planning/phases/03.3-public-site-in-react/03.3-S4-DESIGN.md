### 2.2 Three new primitives in `components/ui/`

Each is written so the dashboard and later pages can use it. Values from `tokens.json` only.

1. **`components/ui/rich-text.tsx` — `RichText`.** Renders a post body from typed blocks (3.3): `paragraph`
   → `<p>`, `heading` → `<h2 id>`, `quote` → `<blockquote>` on `--color-teal-tint` with `text-heading`
   display type (board 5k). No `dangerouslySetInnerHTML` anywhere: the block set is closed and every block is
   plain text. Props `{ blocks, className? }`. Other users: the legal pages and Content › Pages in Phase 6
   (D-91), and the dashboard editor's preview in Phase 3.2.
2. **`components/ui/on-this-page.tsx` — `OnThisPage`.** `<nav aria-label="On this page">` with a 12px muted
   label and one 44px row per heading (`border-bottom` hairline), each a plain `<a href="#id">`. Works with
   JavaScript off. **Renders nothing below two headings** — a list of one, or of none, is not a control.
   Desktop: the 240px column beside the article (board 5k); phone: above the article. No scroll-spy: it would
   be a second moving part for a list nobody can see today. Other users: legal pages (Phase 6).
3. **`components/ui/copy-link.tsx` — `CopyLinkButton`.** The board's `Copy link`, a secondary 44px button.
   Copies the page's canonical absolute URL (never `window.location`, so no query string or hash leaks into a
   shared link) with `navigator.clipboard.writeText`; success toasts `Link copied`, failure toasts `Could not
   copy the link` with the address. **Rendered only after hydration and only when `navigator.clipboard`
   exists**, so a visitor with JavaScript off never sees a button that cannot work. Other users: the guest
   trip page's share in Phase 4, the dashboard's booking reference.

## 3. The data: `lib/data/posts.ts`

Async, Supabase-shaped, `locale` the required first argument, fixtures behind it mirroring storage shape A
(one base row + one record per language), resolved by slice 1's `resolveRow` and `image` in
`lib/data/resolve.ts`. **No component imports a fixture** (held by `tests/data-boundary.test.mjs`, which
covers the new files with no change).

### 3.1 Storage, illustrative (the controller issues migration numbers; none is written here)

```sql
create table posts (
  id uuid primary key default gen_random_uuid(),
  slug text not null unique,
  destination_id uuid references destinations(id),          -- the tag; null = no destination
  cover_image_id uuid references media(id),                 -- 7l "Cover image and alt text"
  featured_stay_id uuid references stays(id),               -- 7l "Featured stay and experience cards"
  featured_experience_id uuid references catalog_items(id),
  published_at timestamptz,                                  -- 7l "Schedule or publish"; null = draft
  is_published boolean not null default false,
  is_sample boolean not null default false,
  sample_fields text[] not null default '{}',
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);

create table post_translations (
  post_id uuid not null references posts(id) on delete cascade,
  locale text not null check (locale in ('en','ar','es')),
  title text not null,
  excerpt text not null,                                     -- the card teaser
  body jsonb not null default '[]',                          -- 7l "Rich text editor in three languages"
  seo_title text, seo_description text,                      -- 7l "Search title and description"
  status text not null default 'draft' check (status in ('published','draft')),
  is_locked boolean not null default false,
  updated_at timestamptz not null default now(),
  primary key (post_id, locale)
);
```

**Why `body` is `jsonb` when slice 1 rejected a `jsonb` translations column.** Slice 1 rejected one blob
holding *all three languages* (types lost, no per-language state). Here each language keeps its own row,
status and lock; only the ordered content of one article in one language is a document, which is what
`jsonb` is for. Supabase types it as `Json`, so `posts.ts` narrows it with a small runtime parser (3.3): an
unknown block type or a missing field **fails the build**, it never renders.

### 3.2 Types (added to `lib/data/types.ts`)

```ts
/** One block of a post body. Closed set; plain text only. */
export type PostBlock =
  | { type: "paragraph"; text: string }
  | { type: "heading"; text: string; id: string } // id: "section-1", "section-2"... locale-independent
  | { type: "quote"; text: string };

export type Post = RowMeta & {
  slug: string;
  /** Card and <h1>: "Colombia's Coffee Triangle: A Journey Through Eje Cafetero". */
  title: string;
  /** The card teaser, published. */
  excerpt: string;
  body: PostBlock[];
  /** The page's <title> and meta, published: "Colombia’s Coffee Triangle — Eje Cafetero". Null = use title / excerpt. */
  seo_title: string | null;
  seo_description: string | null;

  /** ISO timestamptz. Display text is formatted, never stored. */
  published_at: Timestamp;
  /** "Jun 1, 2025" / "1 يونيو 2025" / "1 jun 2025": Intl, month short, Western numerals in Arabic. */
  date_label: string;
  /** Computed from `body` in this locale (3.4). Never typed by hand. */
  reading_minutes: number;

  /** Joined for convenience, like Stay.destination_slug. All null when the post has no destination. */
  destination_id: Uuid | null;
  destination_slug: string | null;
  destination_name: string | null;

  /** Joined slugs; the page reads the rows through stays.ts / experiences.ts. */
  featured_stay_slug: string | null;
  featured_experience_slug: string | null;

  cover_image: ImageRef | null;
  is_published: boolean;
};
```

`HomeStory` (slice 1) stays exactly as it is; it is now a projection of `Post` (3.7).

### 3.3 The module

Internals, written once and kept by Phase 3.2: `parseBody(json)` (validates the block union, assigns
`section-N` ids to headings in order, rejects unknown types), `readingMinutes(blocks, locale)`, `dateLabel(iso,
locale)`, and the joins through `getDestinations` / `getStay` / `getCatalogItem` from slice 1's modules.

**Scheduling, honestly stated.** The site is built ahead of time. A post scheduled for a future
`published_at` appears at the first build after that moment, not at that moment. That is a Phase 3.2 note for
the dashboard's wording, not a change here.

### 3.4 Reading time — computed

`reading_minutes = max(1, ceil(words / 200))`, where `words` counts `isWordLike` segments from
`Intl.Segmenter(locale, { granularity: "word" })` over every block's text in the requested language. One rate
for all three languages, as a named constant. Today: 45, 40 and 37 words → **1 min** on all three, in all
three languages. Rendered `1 min read` / AR and ES through `formatPlural`, so Arabic gets its own plural
forms (the board's `[n] دقائق قراءة` is the plural; one minute takes the singular).

### 3.5 Dates — formatted, not typed

`published_at` holds the published date at 00:00 UTC (`2025-06-01T00:00:00+00:00`, `2025-05-28…`,
`2025-05-24…`). The label is `Intl.DateTimeFormat` with `month: "short"`, `timeZone: "UTC"`, locales `en-US`,
`ar-AE-u-nu-latn`, `es`. **Checked in Node:** it produces `Jun 1, 2025`, `1 يونيو 2025`, `1 jun 2025` —
byte-identical to slice 1's stored `date_label` strings, so the home cards do not move by a character and
`tests/data-contract.test.mjs:268` passes unchanged.
