## What parseStayQuery returns as landed

`{ destination?, guests?, from?, to? }`. No bedroom or query keys. It takes an optional second argument
`{ destinations }` that this page does not use: `stateFromQuery` keeps a destination only if it is a chip the page
renders, which is the stricter check. `stateFromQuery` still maps `bedroomsMin/Max` (exact bucket only) and `query` if a
later `parseStayQuery` returns them.

## Deviations from the plan

1. **[R-4] No own build config; the "same spec passes under the default dev config" criterion is dropped.** The spec is
   `tests/build/private-stays/private-stays.spec.ts` and runs under plan 03's `playwright.build.config.ts`; the default
   config ignores `tests/build/**` by design. I did not run it under that config because it starts `wrangler dev` and
   the controller's brief for this session says no wrangler. The 129 passes are on the production Next server instead
   (same built HTML and the same hydrated client; the Cloudflare static-asset rules are the only difference). The spec
   uses only `baseURL`, so it needs no change for the other runner. Controller command:
   `node scripts/assemble-cloudflare.mjs && PW_PORT=<free> npx playwright test -c playwright.build.config.ts tests/build/private-stays --workers=1`.
2. **[Plan 03 contract] `currentPath` is the English path `/private-stays`**, not `basePath` as Task 3 says. `PublicFrame`
   builds the language links from it with `matchPublicPage`, which only knows English paths; `/ar/private-stays` would
   give the page no language select and no footer language row. No nav link is `aria-current` either way.
3. **[Plan 02 limit] `SectionHead` takes `headingLevel` 2 to 4 only**, so the page `<h1>` could not use it. The same
   head (gold 2px rule, 24px padding, `max-w-3xl`, Questa teal) is written once inline in the page, with `text-display`
   (48 at 768 and up, 32 on a phone: the global phone override of design 2.5; the board draws 48 at all widths). Proposed
   one-line fix in `components/ui/section.tsx` for the controller: `headingLevel?: 1 | 2 | 3 | 4` and an optional size.
4. **[Slimmer props] The client receives `ListStay[]`**, not `Stay[]`: slug, title, neighbourhood, guests, price label,
   capacity, bedrooms, destination and `{src, alt}` of the hero. A `Stay[]` would have shipped about 70 gallery images,
   descriptions and amenities in the page payload for nothing. `ListStay` is a `Pick` of `Stay`, so a field rename breaks
   `tsc`.
5. **[Role] The search field is `type="search"`, so its role is `searchbox`**, not `textbox` (the plan's test 12 says
   textbox). The spec finds it with `getByRole("searchbox")`. Side effect, wanted: `getByRole("textbox")` is 0 on the page.
6. **[Plan 02 behaviour] A card link's accessible name is the picture's alt, the title and the detail line**, not the title
   alone. The spec asserts the name contains the title and that each stay href occurs exactly once.
7. **[Plan 02 finding] `Chip`'s "44px hit area" is 42px.** `after:-inset-y-0.5` is measured from the padding box, so 1px
   of each 2px sits under the 1px border. The ChipGroup spec asserts what is built: 40px visible, hit area reaches 1px
   past each edge and not 4px. Not fixed: `components/ui/chip.tsx` is plan 02's.
8. **[Wider] Test 13 opens the header Menu at 834 as well as 390.** The nav collapses below the 1152px container, which
   covers the tablet width too. The language select is the only combobox in either state.
9. **[Wider] The guests stepper test runs the full 0 -> 11 -> 20 -> max -> 0 path at every width**, not only at 1440.
10. **[Frame copy] `lib/copy/stays-list.ts` also carries `frame.footer`** (Pages, Contact, Instagram, new-tab note, Language,
    copyright). There is no shared source for them yet; nav labels come from `HOME_COPY[locale].nav`. The EN copyright is the
    live footer's line; AR and ES are drafts. Plans 04 and 06 face the same gap, so expect three near-identical blocks
    (see "Before merging").
11. **[Null image] A stay with no hero picture renders a text card with no `<img>`** (MediaCard always draws a picture).
    None of the 12 has that today; the node test renders one to prove it.
