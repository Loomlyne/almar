Why the page plans own their route files: an English `page.tsx` cannot sit next to the Framer `route.ts` it
replaces (Next refuses two handlers for one path), so the delete and the add must be one commit in the page
plan. The AR and ES files go with their English twin so the three always land together
(tests/locale-routes.test.mjs fails if one of the three exists without the others).

Each route file is three or four lines and binds only its locale. Template (names are the recommendation
for the page plans; `components/pages/**` is theirs):
```tsx
// app/ar/private-stays/[stay]/page.tsx
import { StayDetailPage, stayDetailMetadata, stayStaticParams } from "../../../../components/pages/stay-detail-page";
export const dynamicParams = false;
export const generateStaticParams = stayStaticParams;
export const generateMetadata = ({ params }: { params: Promise<{ stay: string }> }) => stayDetailMetadata("ar", params);
export default function Page({ params }: { params: Promise<{ stay: string }> }) { return <StayDetailPage locale="ar" params={params} />; }
```
Rules for those files: no `layout.tsx` under `app/ar` or `app/es` that renders `<html>` or `<body>` (the root
document already does it); no `"use client"` route file; `generateMetadata` merges
`alternates: localeAlternates(locale, path)` and `openGraph.url: absoluteLocaleUrl(locale, path)`; every
internal link is `siteHref(locale, path)`; the nav language select gets `localeHrefs(path)` (plan 02's
`SiteNav localeHrefs` / `LocaleSelect hrefs`); the footer language row gets the same three hrefs. Links that
change locale are plain `<a>` (or plan 02's `window.location.assign`), never `next/link`, so the next
document is always the other locale's prerendered HTML.

lib/locale-path.ts (written in Task 1):
```ts
export const LOCALES = ["en", "ar", "es"] as const;
export type Locale = (typeof LOCALES)[number];          // structurally identical to lib/data/types Locale
export const DEFAULT_LOCALE: Locale = "en";
export function isLocale(value: unknown): value is Locale;
export function localeDir(locale: Locale): "rtl" | "ltr";
export function localePath(locale: Locale, path: string): string;            // "/" -> "/ar/"; "/x" -> "/ar/x"
export function stripLocale(pathname: string): { locale: Locale; path: string };
export function switchLocalePath(pathname: string, target: Locale): string;
export function localeHrefs(path: string): Record<Locale, string>;
export const PUBLIC_PAGES = ["/", "/private-stays", "/private-stays/[stay]"] as const;
export function matchPublicPage(path: string): (typeof PUBLIC_PAGES)[number] | null;
export function siteHref(locale: Locale, path: string): string;
export const SITE_ORIGIN = "https://almarprivatejourney.com";
export function absoluteLocaleUrl(locale: Locale, path: string): string;
export function localeAlternates(locale: Locale, path: string): {
  canonical: string; languages: { en: string; ar: string; es: string; "x-default": string };
};
```
A later slice that converts a page appends its pattern to PUBLIC_PAGES; nothing else changes.

Measured on 2026-10-03 (throwaway Next 15.5.26 project in /tmp, removed; not in the repo):
- `app/ar/page.tsx` prerenders to `.next/server/app/ar.html`; `app/ar/about/page.tsx` to `ar/about.html`; a
  route group adds nothing to the path (`(grp)/inside` -> `inside.html`). Route handlers stay `.body`.
- A `"use client"` component rendered by the root layout, reading `useSelectedLayoutSegments()`, put
  `lang="ar" dir="rtl"` into the prerendered `ar.html` and `ar/about.html`, `lang="es" dir="ltr"` into
  `es.html`, and `lang="en"` into `_not-found.html`. Under `next start`, `/ar/nope` served the prerendered
  `_not-found` with `lang="en"` and the client kept `en`, so nothing mismatched. A soft navigation /ar -> /es
  updated the attributes to es/ltr. No hydration or console error. (Using `usePathname()` instead would have
  set `ar` on the client for `/ar/nope` while the served HTML said `en`. That is why segments are used.)
- `metadata.alternates` with absolute URLs is printed as given: `/ar/` keeps its slash, `/ar/about` has none.
  Next prints the attribute as `hrefLang` (camelCase). HTML attribute names are case-insensitive, so CSS
  selectors match it, but **raw-HTML regexes must use the `i` flag**.
- In this repo's build output today, `account.html`, `dashboard/*.html`, `login.html`, `booking/trip.html`,
  `bookings.html` and `_not-found.html` exist and are ignored by the assembler, which only copies `.body`.
  They must stay out of `out/`.

Node loading: the assembler and node tests import `.ts` with Node >= 22.18 type stripping. Node does not
resolve extensionless relative imports, so `lib/locale-path.ts` has no value imports, and
`lib/not-found-document.ts` imports only `node:` built-ins plus `import type` (stripped by Node).

Local Cloudflare: `./node_modules/.bin/wrangler dev` in its default local mode (workerd, never `--remote`)
serves `out/` with `wrangler.toml`'s `[assets]` block (`auto-trailing-slash`, `404-page`). No login and no
API call is needed. If wrangler asks for a login or an account, stop and report: never `wrangler login`.
