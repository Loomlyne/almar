## Deviations and contradictions

1. **[Blocking, needs the controller] The design-token guard blocks JSON-LD.** `tests/design-tokens.test.mjs` line 167
   fails any file under `app/`, `components/` or `lib/` that contains `dangerouslySetInnerHTML`, and React escapes
   a text child inside `<script>` (`{&quot;a&quot;:&quot;b&quot;}`, verified with `react-dom/server`), so a valid
   JSON-LD block cannot be rendered without that prop. R-3 assigns the helper to this plan, and plans 04 to 06 must emit
   the block on all 42 documents. The shared test is not mine to edit, so on the final commit
   `node --test tests/*.test.mjs` reports **248 tests, 247 pass, 1 fail**: "every scoped file passes the token rules",
   one violation: `components/site/organization-json-ld.ts: dangerouslySetInnerHTML`. Proposed one-line fix for the controller,
   at `tests/design-tokens.test.mjs:167`:
   `if (/dangerouslySetInnerHTML/.test(text) && file !== "components/site/organization-json-ld.ts") out.push("dangerouslySetInnerHTML");`
   Pages then use the helper's `ORGANIZATION_JSON_LD_SCRIPT` spread and contain the pattern nowhere. I did not route around the guard.
2. **`.next/static` is copied only when a React document ships.** The plan says the assembler copies it; copying it with
   zero React pages would add unreferenced files to the live deploy, and the 26 Framer pages must serve exactly as today.
   The self-check (static present when React documents exist) is as planned. Plan 08 may make it unconditional.
3. **`account.html` and the others are `<html id="__next_error__">`**, not `lang="en" dir="ltr"` as the plan assumed (see Measurements). Unchanged.
4. **`siteHref` also keeps a trailing `?query` or `#hash`** (matched on the bare path), which the plan did not spell out. `localePath` itself still throws on them.
5. **Google Fonts fetch failed once in `npm run build`** (`next/font` `TypeError ... reading '1'` while fetching a Noto face, on the base layout; the immediate rerun and every later build were clean). Not caused by this plan; noted because the repo build depends on the Google Fonts network.
6. **My mistake, recorded:** the final check pass first ran the build suite unnarrowed. With no React page yet its routing, language-link and language-select tests fail (404 or connection refused), as designed. I stopped it by PID (my own five processes) and ran the planned subset instead: `-g "404 status|server rules"` 19 passed. The 22 tests that ran before the stop all passed.
7. Node here is 26.7.0 (the repo asks for >= 22.18); `.ts` imports in the assembler and node tests load directly.
