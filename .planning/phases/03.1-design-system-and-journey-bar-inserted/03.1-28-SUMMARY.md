# Phase 3.1 Plan 28: Harness matrix, RTL and a11y proof Summary

76 scenes across 11 components are screenshotted in EN, AR and ES at the widths where they exist (411 committed baselines), and every scene is checked for RTL (DSGN-03) and accessibility (DSGN-05). The specs found and fixed two real defects.

## What was built
- **matrix.ts**: state lists come from the `scenes` export of each `tests/journey/scenes/*.tsx` (read as text), widths per component from the UI-SPEC state matrix. Phone-only (sheet, phone rail, phone row, cart dock, phone cart) and 768-up (bar, segment, rail, rail cart, add-on rows) skip N/A widths.
- **visual.spec.ts**: `toHaveScreenshot` on the union of `#harness-root`, open dialogs, popovers and fixed children, `animations: disabled`, Next dev overlay hidden by `visual.css`, finite entrance animations awaited before the rectangle is measured. **Blank-page guard**: `settle()` waits for a visible root with children and no `harness-unknown` (one reload retry for the dev server's first-compile blank), a `beforeAll` warms every component, and each test asserts the capture has size and draws text, an SVG, an image or a dialog before a baseline can exist. Two states whose contract is "renders nothing" (team-section `none`, inclusions-list `empty`) assert emptiness instead of a picture.
- **rtl.spec.ts** (142 tests): for every scene in AR at each valid width: `dir=rtl`, `lang=ar`, no horizontal page overflow, every `scale-x-100` glyph is mirrored versus the same scene in EN, no svg is mirrored without that utility, dates and `ALMAR-` references inside `<bdi>`/`dir=ltr`. Positional: bar Where/Who order, StepRail order, stepper minus at inline-start, cart Remove at inline-end, sheet dialog rtl.
- **a11y.spec.ts** (421 tests): every scene in EN: icon-only buttons/links have `aria-label`/`aria-labelledby`; every svg is `aria-hidden` or inside a named control; every svg uses `currentColor`; every Tab stop has the 2px teal outline, offset 2px (JourneySegment 3px inset rule is the only allowed replacement); the first Tab lands on the first tabbable in closed scenes and stays inside open dialogs; Tab order follows visual order (LTR and RTL) for bar, sheet, StepRail, cart and guest panel.
- **Report**: `.planning/phases/03.1-design-system-and-journey-bar-inserted/03.1-HARNESS-REPORT.md`, a row per scene with canvas board, frame, URL and image paths.

## Deviations from Plan
1. **[Rule 3] matrix.ts reads scene files as text instead of importing the modules.** Importing them pulls in components that import `.svg` files (`team-section.tsx`), which Playwright's Node loader cannot parse. Drift is still caught: an unknown state renders `harness-unknown`, which `settle()` rejects. `grep -c scenes tests/journey/matrix.ts` is 7 (plan asked for 11 imports).
2. **[Rule 1] AddOnRow stepper wrapped.** The control column was 124px, a 44px stepper needs 132px, so plus dropped under minus at desktop and tablet (visible in the first baselines). Column is now `w-34` (136px). Baselines regenerated.
3. **[Rule 1] JourneyCart stay dates were not in `<bdi>`** (DSGN-03 failure in AR). Wrapped in `<bdi dir="ltr">`.
4. **Add-on rows have no 390 baseline** except `phone-row`; the row layout is 768-up and the phone uses the phone row (UI-SPEC). The first draft captured them at 390 and they overflowed by 9px.
5. **Plan asked for image names `journey/__screenshots__/...` as one string.** Playwright flattens slashes to dashes, so the name is passed as a path array; files land in `tests/journey/__screenshots__/` as specified.
6. **Ring colour measured at rest.** `transition-colors` fades the outline colour in, so mid-fade reads ivory or ink; the spec awaits the element's animations. The rendered ring is teal.
7. **Cart stepper check** in the plan text (password eye, /login) is not in this harness and is not asserted.
8. **Plan 25 gap closed:** two new sheet scenes (`stay-locked`, `blocked-when`) and three tests cover `lockDestination` and `blockedDates`.
9. Baseline count is 411 (plan asked for at least 300).
