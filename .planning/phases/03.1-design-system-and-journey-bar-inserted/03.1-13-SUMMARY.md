## Deviations from Plan

1. **[Rule 3] Rail breakpoint 1280px, not 1439px.** No arbitrary values allowed; `xl` is the nearest standard step. Between 1280 and 1439 px the rail now shows instead of the Menu button. 1440 screens are unchanged.
2. **[Rule 3] Off-scale spacing `pt-22`** (drawer top padding, 88px) rejected by the guardrail; used `pt-16` (64px), which clears the now shorter header.
3. **[Rule 1] tests/phase-03-dashboard.spec.ts edited.** The known "New booking opens one sidebar" failure was NOT a layout problem. The table was found before the click and lost afterwards: Radix sets `aria-hidden` on everything behind an open modal, so `getByRole("table")` stops matching. The spec now uses `page.locator("table")` for the same width assertion. It passes (it also failed before this plan, identically). Root cause found; the deferred item can be closed.
4. **Commit sweep.** Between my staging and my Task 2 commit, the orchestrator's `docs(03.1)` commit b9a5d38 picked up my staged files (layout polish, profile, settings, settings test, deletion of tests/legacy/13.json). The content is correct and in the tree, but it sits under a docs commit message. No history rewritten.
5. **Shard 13 handling.** Task 1 trimmed tests/legacy/13.json to profile and settings so the guardrail stayed green at the Task 1 commit; Task 2 deleted it.
6. **Visual polish after a screenshot:** logo box `aspect-2/1` (the lockup rendered 140px tall) and rail `gap-0` so items are contiguous like the canvas.
