# Phase 3.1 — UI Design Contract

> Visual and interaction contract for Phase 3.1. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

Phase 3.1 has two outputs. The first is the design system on the claude.ai canvas (https://claude.ai/artifact/6MqV4cd2KzXLsVputN2ctw). The second is the repo: one `tokens.json`, Tailwind v4 everywhere, and the 11 journey components proven in a test harness. The canvas is the visual source of truth. This file sets the rules the canvas and the code must both follow.

Precedence (D-01): every 2026-09-28 decision beats `01-UI-SPEC.md`. The rules that change are listed in [Supersedes 01-UI-SPEC](#supersedes-01-ui-spec). Where the audit boards disagree with a locked decision, see [Board deltas](#board-deltas). Rules from 01 that still hold are listed in [Kept from 01-UI-SPEC](#kept-from-01-ui-spec).

shadcn gate: there is no `components.json`, and Phase 1 D-21 forbids shadcn. The gate answer is no. Do not run `shadcn init`.

Sources: `03.1-CONTEXT.md` (D-01…D-60, D-32a, D-32b), `03.1-RESEARCH.md`, audit boards (`BookerKit`, `Hero`, `HeroPhone`, `PhoneWhere/When/Who`, `Flow`, `FlowPhone`, `Drift`), `01-UI-SPEC.md`, `CLAUDE.local.md`. The installed Tailwind 4.3.3 source was checked for theme-namespace lookups (see [Token contract](#token-contract)).

## Spacing Scale

Components use Tailwind's numeric spacing utilities (base `--spacing: 0.25rem`). Only these steps are allowed on padding, margin, gap, and inset:

| Token | Value | Utility step | Usage |
|-------|-------|--------------|-------|
| xs | 4px | `1` | Icon gaps, progress-bar gaps, label-to-value gap in a JourneySegment (`gap-1`), gap between calendar day cells (`gap-1`) |
| sm | 8px | `2` | Compact spacing, dense padding, chip inner gap |
| md | 16px | `4` | Default spacing, phone column inset, row padding, panel inner gap |
| lg | 24px | `6` | Segment padding-inline, panel padding, card padding, gap between groups |
| xl | 32px | `8` | Layout gaps, tablet column inset, gap between rail and main |
| 2xl | 48px | `12` | Section breaks, gap between the two calendar months |
| 3xl | 64px | `16` | Page-level spacing, desktop column inset |

Exceptions (declared):

- `3` (12px): every 12px use in this spec. That covers the gap inside controls (icon to label, stepper parts), the gap between add-on rows, AddOnRow padding (`p-3`), the DestinationMenu panel block padding (`py-3`) and GuestPanel top padding (`pt-3`), the search alert line (`py-3`, `mt-3`), InclusionsList row gap (`gap-y-3`) and phone compact padding (`py-3`), JourneyCart line gaps and rule padding (`gap-3`, `pt-3`), StepRail item gap (`gap-3`), and the phone add-on row gap (`gap-3`). The boards' 10, 12, and 14px gaps snap to 12.
- `0.5` (2px): only the FilterChip hit-area extension (`after:-inset-y-0.5` turns the 40px chip into a 44px hit target). It is never used as a layout gap.
- `px` (1px) for hairlines only.

Do not name spacing tokens `xs`/`sm`/`md`/`lg`/`xl` inside `@theme`. Tailwind 4.3.3 resolves `max-w-*` through `--max-width`, `--spacing`, then `--container`, and `w-*` through `--width`, `--spacing`, then `--container`. A `--spacing-md: 16px` token silently turns `max-w-md` into 16px. The existing `--spacing-xs…3xl` entries are removed from `@theme`. `tokens.json` keeps them under `space` for the canvas only, and emits them as `--space-*`, which is not a Tailwind namespace.

Dimension tokens (in `@theme` as `--spacing-<name>`, so `h-`, `w-`, `size-`, and `min-h-` all work). These are sizes, not spacing steps:

## Typography

Seven named steps (D-19). This locked decision replaces the template's 4-size cap. 12px is the floor. Every size literal in the codebase maps to one step or is deleted.

| Step | Token / utility | Size ≥768px | Size <768px | Line height (Latin) | Line height (Arabic) | Face | Weight |
|------|-----------------|-------------|-------------|---------------------|----------------------|------|--------|
| caption | `text-caption` | 12px | 12px | 1.5 (18px) | 1.7 | Lato | 400 |
| label | `text-label` | 14px | 14px | 1.43 (20px) | 1.63 | Lato | 400 |
| body | `text-body` | 16px | 16px | 1.5 (24px) | 1.7 | Lato | 400 |
| title | `text-title` | 20px | 20px | 1.3 (26px) | 1.5 | Questa (names), Lato 700 (totals) | 400 / 700 |
| heading | `text-heading` | 32px | 24px | 1.2 | 1.4 | Questa | 400 |
| display | `text-display` | 48px | 32px | 1.1 | 1.3 | Questa | 400 |
| hero | `text-hero` | 64px | 40px | 1.05 | 1.25 | Questa | 400 |

Implementation:

- `@theme` declares `--text-<step>` and `--text-<step>--line-height`.
- The phone sizes are fixed token values. `@layer base` sets `--text-hero: 40px; --text-display: 32px; --text-heading: 24px` on `:root`, then restores 64/48/32 inside `@media (width >= 48rem)`. Components never write `md:text-hero`.
- Arabic line heights: `@layer base` overrides each `--text-<step>--line-height` under `:root:lang(ar)` (+0.2).
- Custom variant `ar:` = `&:where(:lang(ar), :lang(ar) *)`, declared once in `globals.css` with `@custom-variant`. It removes uppercase and tracking: `uppercase tracking-kicker ar:normal-case ar:tracking-normal`.
- Faces: `font-display` → Questa (Latin) or `var(--font-noto-naskh)` under `:lang(ar)`. `font-body` → Lato or `var(--font-noto-sans)` under `:lang(ar)`. The swap lives in `@layer base` custom properties, not in components.
- Tracking tokens: `--tracking-kicker: 0.12em` (`tracking-kicker`) and `--tracking-display: -0.02em` (`tracking-display`, on hero and display only).

Weights. There are exactly two: 400 and 700. Questa is 400 only; never synthesize a bold. Lato 700 is allowed only on:

1. Arrive and leave day numerals in the calendar.
2. The count between stepper buttons (guest and add-on steppers). Recorded under D-22 "selected values": the count is the value the guest has selected.
3. The Total line in JourneyCart, and the phone total amount.
4. The one error line per view: the search alert line (desktop and tablet) or the phone sheet warning line (phone). Recorded under D-22 "the one error line". Each view shows only one of them.

Uses 2 and 4 are kept as drawn on the boards. They are marked for owner confirmation at the Foundations/Components canvas gate (see [Owner questions at the canvas gate](#owner-questions-at-the-canvas-gate)).

Everything else is 400, including button labels, segment labels, chip labels, nav, StepRail labels, and prices that are not totals.

## Token contract

`tokens.json` at the repo root is the one source (D-11). `scripts/generate-theme.mjs` writes it into `app/globals.css` between `/* GENERATED:THEME:START */` and `/* GENERATED:THEME:END */`. The same file is installed on the canvas as its design system. Values stay CSS custom properties inside `@theme` (not `inline`), so Phase 5 Settings › Brand can override them at runtime (DSGN-04).

Shape (keys are what the generator emits after `--`):

```
color.{ivory, surface, teal, teal-hover, teal-press, teal-tint, gold, ink, muted, line, error, success, warning, whatsapp}
text.{caption, label, body, title, heading, display, hero}  + "--line-height" for each
font.{display, body}                    (Questa/Lato with Noto swap under :lang(ar))
tracking.{kicker, display}
spacing.{control, chip, bar, bar-docked, summary, entry, action, sheet-head, dock, mark, search, rail-offset, row, row-dense, chip-dense}
container.{column, menu, calendar, rail, dialog, sidebar}
radius.{control, overlay} = 0
shadow.{float, lg, rule-primary, rule-error, rule-today, selected}
ease.{standard}
transition-duration.{fast, mid}
animate.{panel-in, sheet-in, dock-in, fade-in}
space.{xs, sm, md, lg, xl, 2xl, 3xl}    (canvas reference only → --space-*, no utilities)
```

Shadow tokens (from BookerKit; D-29 bans arbitrary `shadow-[…]`):

| Token | Value | Utility | Use |
|-------|-------|---------|-----|
| `--shadow-float` | `0 18px 40px -10px rgb(10 9 7 / 0.3), 0 4px 10px -4px rgb(10 9 7 / 0.1)` | `shadow-float` | Hero JourneyBar, phone entry |
| `--shadow-lg` | `0 28px 56px -16px rgb(10 9 7 / 0.28), 0 10px 20px -10px rgb(10 9 7 / 0.12)` | `shadow-lg` | Panels, menus, select list, alert line, dialogs, toast (replaces `--shadow-overlay`) |
| `--shadow-rule-primary` | `inset 0 -3px 0 var(--color-teal)` | `shadow-rule-primary` | Open or focused segment, StepRail current |
| `--shadow-rule-error` | `inset 0 -3px 0 var(--color-error)` | `shadow-rule-error` | Missing segment |
| `--shadow-rule-today` | `inset 0 -2px 0 var(--color-teal)` | `shadow-rule-today` | Today day cell |
| `--shadow-selected` | `inset 0 0 0 2px var(--color-teal)` | `shadow-selected` | Added AddOnRow, ToggleCard on |

Docked bar, sticky header, and docks have no shadow, only a hairline (01 D-65 kept).

`lib/cn.ts` registers these with `extendTailwindMerge`: font-size group `text-{caption…hero}`; text-color and bg-color groups for every `color.*` key; the shadow group for every `shadow.*` key. Without that, `twMerge` treats `text-body` and `text-teal` as the same conflict group and drops one (RESEARCH Pitfall 2).

Guardrail (D-29, extends `tests/design-tokens.test.mjs`) fails on:

- arbitrary values `[...]` in any class;
- physical utilities `ml-`, `mr-`, `pl-`, `pr-`, `left-`, `right-`, `text-left`, `text-right`, `rounded-*` other than `rounded-none`, `border-l-`, `border-r-`;
- any hex outside `tokens.json`;
- `bg-gold`, `text-gold`, `fill-gold`, `stroke-gold`;
- numeric spacing steps outside `{0, px, 0.5, 1, 2, 3, 4, 6, 8, 12, 16}` on `p*`, `m*`, `gap*`, `space-*`, `inset*`, `top-`, `bottom-`, `start-`, `end-` (named dimension tokens such as `top-rail-offset` are allowed);
- any `*.module.css`;
- `font-bold` outside the files that own the four 700 uses (allowlist: `journey-cart.tsx`, `stepper.tsx`, `date-range-panel.tsx`, `journey-bar.tsx`, `journey-sheet.tsx`).

Framer `route.ts` files are excluded.

## Radius, border, elevation

- Radius 0 everywhere (`rounded-none` is the default; any other `rounded-*` fails the guardrail).
- Hairline: `border border-line` for dividers, price lines, row separators, header underline.
- Control outlines: `border-muted` at rest (chips, select trigger, ToggleCard off), `border-teal` for teal controls (stepper, Add toggle, secondary button), `border-ink` for text inputs (01 kept).
- State borders: teal (selected, focus rule), error (missing, field error), gold 1px (confirmed chip only).
- Elevation: `shadow-float` (bar), `shadow-lg` (panels, dialogs, toast). No hover lift.
- Image outline (01 kept): `outline outline-1 -outline-offset-1 outline-ink/10` on photos.

## Motion (D-44)

| Token | Value | Use |
|-------|-------|-----|
| `--transition-duration-fast` | 150ms | `duration-fast`: hover, press, color, bar docking |
| `--transition-duration-mid` | 250ms | `duration-mid`: panels and sheet enter/exit |
| `--ease-standard` | `cubic-bezier(0.2, 0, 0, 1)` | `ease-standard` |
| `--animate-panel-in` | `panel-in 250ms var(--ease-standard) both` | Desktop and tablet panels: opacity 0→1, translateY 8px→0 |
| `--animate-sheet-in` | `sheet-in 250ms var(--ease-standard) both` | JourneySheet and phone cart: opacity 0→1, translateY 8px→0 from the block end |
| `--animate-dock-in` | `dock-in 150ms var(--ease-standard) both` | Docked bar and phone docked row: opacity 0→1, translateY -8px→0 |
| `--animate-fade-in` | `fade-in 150ms linear both` | Reduced motion for all of the above |

- Keyframes live inside `@theme` so they generate `animate-*` utilities. No module CSS.
- `motion-reduce:animate-fade-in` on every animated element. No bounce, no spring, no stagger, no scale.
- Transitions use `transition-colors` or `transition-opacity` only, with `duration-fast ease-standard`. Never `transition-all`, never an arbitrary `transition-[…]`.
- Hover darkens, press darkens more. No transform on hover or press (01 kept).

## Layout, breakpoints, layers

- Breakpoints: Tailwind defaults. Phone `<768px` (below `md`). Tablet `768–1023px` (`md`). Desktop `≥1024px` (`lg`). No custom breakpoint.
- Harness and canvas frame widths: phone 390×844, tablet 834×1194, desktop 1440×900.
- Logical properties only (`ms/me/ps/pe/start/end`, `text-start/end`, `border-s/e`). Chevrons, arrows, the search glyph, panels, the rail, and dialog actions flip with `dir` (`rtl:-scale-x-100` on directional glyphs). Check, plus, minus, and close do not flip.
- Layers: sticky header (and the docked bar in it) `z-40`; journey panels and popovers `z-45`; toasts `z-50`; WhatsApp `z-60`; dialogs, JourneySheet, and phone cart `z-70`.
- Sticky header: solid ivory, hairline under it, no shadow. When the bar docks, the header gains a second row and the hairline moves under that row.

### Link (`components/ui/link.tsx`)

- Standalone links (nav, `Back to stay`, `Change`, `Edit search`): `text-teal`, no underline at rest, `hover:underline decoration-gold decoration-1 underline-offset-4`, and the focus ring.

## Harness (D-32, D-32a)

- The route renders only when a test flag is set (for example `ALMAR_HARNESS=1` in the Playwright web server env). Without the flag it calls `notFound()` in dev and production. It is excluded from the Cloudflare assemble step and `robots`, is never linked, and is never called a design system.
- Next.js App Router treats folders that start with `_` as private, so `app/__harness/` would never route. Use `app/%5F%5Fharness/` (URL `/__harness`) or a name without the leading underscore.
- URL shape: `/__harness?c={component}&s={state}&l={en|ar|es}`. The page sets `lang`/`dir` on `<html>` through `lib/set-document-locale.ts`, then renders the component with fixtures from `tests/journey/fixtures.ts`.
- Specs: every component × every non-N/A state × EN/AR/ES × phone/tablet/desktop, `toHaveScreenshot`, compared with the canvas frames by the owner at the Journey gate.
