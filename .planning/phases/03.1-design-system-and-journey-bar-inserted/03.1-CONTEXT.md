# Phase 3.1: Design system and journey bar - Context

**Gathered:** 2026-09-28
**Status:** Ready for planning

<domain>
## Phase Boundary

One consolidated design system and the journey/booking components built on it, before any new page.

- The design system lives on the claude.ai Design canvas "ALMAR Design System Audit" (https://claude.ai/artifact/6MqV4cd2KzXLsVputN2ctw), extended into the full system. It replaces `/design`. `/design` and `/framer` are deleted from the repo.
- Code side: one token file, the whole stylesheet layer moved to Tailwind v4, patches folded in, logos from `brand/`, one `next.config.ts`, the fake team removed from React code and copy, and the journey components coded and proven against the canvas in a test harness.
- No backend, no catalog data, no new public route. The live site at `/` stays Framer until 3.3.

## Implementation Decisions

### Precedence
- **D-01:** Every decision and change made on 2026-09-28 (the audit boards, `CLAUDE.local.md` "Decisions 2026-09-28", and this discussion) wins over older docs. Where `01-UI-SPEC.md` or Phase 1 CONTEXT conflicts, the older line is superseded, not patched. Superseded in particular: the 40px control radius and 64px overlay radius (now 0), radio controls and radio cards, circle gold steppers, gold primary fill, the secondary-style Search, gold calendar rings, the unnumbered booking steps, the phone monogram logo, the four-size type cap, "English only" copy, and every `/design` route rule.

### Design system home (the canvas)
- **D-02:** The existing audit canvas is extended and becomes the primary design system. There is no other design surface. Owner words: "Replace /design with that canvas. I don't want to say /design anymore. I want that canvas to be the primary one for the design system and everything."
- **D-03:** The canvas has 7 pages: 1 Audit (current boards 1–8a, frozen) · 2 Foundations (tokens, type, space, motion, dense) · 3 Components (every control in every state) · 4 Journey (desktop bar, phone sheet, add-ons, cart, pay steps) · 5 Public pages (the 11 Framer templates as layouts) · 6 Guest (login, account, bookings) · 7 Dashboard (every screen and sidebar).
- **D-04:** Full scope in 3.1, including the full dashboard (every screen from Phase 3 D-01…D-55).
- **D-05:** Dashboard and guest screens are drawn in two states: empty (the real Phase 3 "No [things] yet" line) and filled with clearly marked placeholders (`[Guest name]`, `ALMAR-000000`, `AED [AMOUNT]`). No invented people or numbers.
- **D-06:** Values come from Framer's layout, sections and spacing rhythm, drawn with the brand-book values and this type scale. Framer's drift (6 teals, 4 ivories, 23 sizes) is not copied.
- **D-07:** Each board has an EN / AR / ES switch, and Arabic flips to RTL. Each key screen also has one fixed Arabic RTL frame so RTL is always visible side by side.
- **D-08:** Claude drafts AR (Gulf-friendly Modern Standard Arabic) and ES (neutral Latin American) from the real Framer EN copy. The owner reviews them at the canvas gate.
- **D-09:** The canvas is built first. Sign-off is per page: Foundations + Components first. After that sign-off the Tailwind conversion may start while Journey, Public, Guest and Dashboard are drawn. Each page has its own gate.
- **D-10:** Real images come from `public/assets/img/` (mapping in the audit README), uploaded as canvas assets. Brand logos and fonts come from `brand/`.

### Tokens
- **D-11:** One `tokens.json` in the repo is the source. It generates the Tailwind `@theme` and is installed on the canvas as its design system, so the canvas Theme menu shows the same named tokens. Tokens stay CSS custom properties so Settings › Brand can override them at runtime in Phase 5 (DSGN-04).
- **D-12:** Palette: ivory `#fffaf0` (bg), white `#ffffff` (surface), teal `#1f3b40` (primary), `--color-teal-tint` `#d1dfe0` (backgrounds only, never text), gold `#d4ba8a` (lines only), charcoal `#262626` (ink), muted `#63615f`, line charcoal at 16%, error `#8f2d2d`, plus success, warning and WhatsApp green from 01-UI-SPEC.
- **D-13:** The primary button is a teal fill with an ivory label. Gold is never a button fill, never text, and never an icon. Gold is only a rule or line: the journey bar's 2px top rule, section rules, the active nav underline, the current-step rule, the confirmed-chip hairline, and link hover.
- **D-14:** Link hover: the text stays teal and a 1px gold underline appears. This replaces the old no-underline lock (Phase 1 D-45).
- **D-15:** The saved heart, stepper outlines, calendar start/end and the close buttons (phone menu, photo viewer) are all teal.
- **D-16:** Radius 0 everywhere. No pills. Touch targets are at least 44px.
- **D-17:** Radio controls are replaced by toggle cards: square cards, each a button with `aria-pressed`, one on at a time, teal border when on. This applies to deposit/full and the UAE airport.
- **D-18:** Dense (dashboard) tokens are defined in 3.1 on the same scale (table row, stat number, chip, sidebar) and drawn on the canvas. 3.2 applies them to the real screens.

### Type scale
- **D-19:** Seven named steps: caption 12 · label 14 · body 16 · title 20 · heading 32 · display 48 · hero 64. The boards' 13 and 15 snap to 12 and 16. Every size literal in the codebase maps to one of these steps or is deleted. 12px is the floor.
- **D-20:** Below 768px: hero 64→40, display 48→32, heading 32→24, as fixed token values per breakpoint. Body, label and caption don't change.
- **D-21:** Arabic uses the same named steps with about +0.2 line-height, and no uppercase or letter-spacing. Faces: Noto Naskh Arabic for headings, Noto Sans Arabic for UI.
- **D-22:** Weights: Questa 400 only. Lato 400 and 700; 700 is allowed on selected values, totals and the one error line.
- **D-23:** Kickers ("Welcome to ALMAR"): caption 12, uppercase, +0.12em tracking, muted. Arabic uses sentence form.
- **D-24:** The title step (20) is Questa: card, add-on, stay and destination names. Lato is for UI values, labels and body.

### Styling method
- **D-25:** Tailwind v4 for everything. This was the owner's choice; Claude had recommended CSS modules.
- **D-26:** Convert all of `app/globals.css` (6,183 lines), `app/home-preview.css` and the 15 `*.module.css` files (1,388 lines) into utilities on the components. The 47 "Comment N" patches fold into those classes. No `*.module.css` remains.
- **D-27:** ROADMAP success criterion 2 is reworded: styles live in the component. `globals.css` holds only `@import "tailwindcss"`, `@theme` (generated from `tokens.json`) and a small `@layer base` (reset, html/body, fonts, focus-visible, `::selection`). No selectors keyed to route or specimen ids, and no styles that depend on a parent like `.nav-tools`.
- **D-28:** Variants use `class-variance-authority` + `tailwind-merge`.
- **D-29:** A repo test fails on: arbitrary values (`bg-[#…]`, `text-[13px]`, `rounded-[…]`), physical utilities (`ml-`, `mr-`, `pl-`, `pr-`, `left-`, `right-`, `text-left`, `text-right`), and any hex outside the token source. Framer `route.ts` files are excluded.
- **D-30:** Proof the conversion didn't break the look: Playwright screenshots before and after in EN and AR at phone, tablet and desktop, on `/dashboard`, `/account`, `/login` and `/booking/trip`. Only intended changes may differ (teal primary, gold underline, square corners, the fixed `/account` select). The existing tests stay green or are ported.
- **D-31:** Order inside 3.1: canvas Foundations + Components (gate) → `tokens.json` + `@theme` → Tailwind conversion, logos, `next.config.ts`, fake team removal, `/design` and `/framer` removal → coded journey components → harness screenshots against the canvas.

### Coded components and verification
- **D-32:** The owner UATs the design on the canvas. The coded React components are proven in a Playwright component-test harness with no route: every component in every state, EN/AR/ES, at phone, tablet and desktop, compared with the canvas frames. The components are mounted on real pages in 3.3 (home hero) and 4 (`/booking/trip`).
- **D-33:** Components to build: JourneyBar, JourneySegment, DestinationMenu, DateRangePanel, GuestPanel, JourneySheet (phone), StepRail, AddOnRow, InclusionsList, JourneyCart, TeamSection. They take no hard-coded strings and no seeded catalog data. Destinations, add-ons, inclusions, prices and team arrive as props (fixtures in tests and on the canvas).
- **D-34:** Delete `/design` (`app/design/**`) and `/framer` (`app/framer/**`, including the hero-booker injection). Owner words: "/Framer will be removed, as will /design... we'll only keep the canvas." Live `/` and the other Framer `route.ts` pages keep serving. The 404 assemble step (`app/[...not_found]/route.ts` → `out/404.html`) must keep working.

### Journey bar (desktop and tablet)
- **D-35:** From 768px up: the 72px bar (Destination · Dates · Guests · Search). Labels are in normal case, values in Lato 16, and gold is the 2px top rule only. On tablet the panels open full width under the bar and the calendar shows one month. On desktop the calendar shows two months.
- **D-36:** Segment states: Empty, Hover, Open/focus (white fill, 3px teal rule inside the segment), Filled, Missing after Search (3px error rule, error label, and one alert line). Focus elsewhere is a 2px teal outline.
- **D-37:** Search is teal primary. It checks the fields and is never disabled. Search never charges.
- **D-38:** After scrolling past the hero, a compact JourneyBar (same values, shorter) docks into the sticky header. Clicking a segment opens the same panel.
- **D-39:** DestinationMenu: one destination per journey. Each row is the name plus a short line the owner writes per destination in Dashboard › Catalog › Destinations, in EN/AR/ES (e.g. "[Walled city and Caribbean islands]"). The canvas shows it as a bracketed placeholder. No Packages or multi-city line in 3.1.
- **D-40:** Dates: past days are muted and can't be picked, and departure must be at least 1 night after arrival. All other rules (minimum nights, blocked nights, too late to book) come from the stay later and show as a reason, never as a block in the bar. DD/MM/YYYY, weeks start Monday, Western numerals. Arrive/leave days are solid teal; nights in between are `--color-teal-tint`.
- **D-41:** The Guests value lists each non-zero group by name: "2 adults", "2 adults, 1 child, 1 infant". Plurals come from locale plural rules (Arabic dual and plural forms). Adults' floor is 1; children and infants have a floor of 0. The bar never blocks on guest count.

### Phone journey
- **D-42:** Below 768px: one tap target in the hero, "Plan your journey · Where · When · Who". It opens a full-screen sheet, one question per screen (Where → When → Who), with a progress bar, "n of 3", Back and Close. Tapping a destination moves on by itself. The bottom bar shows the summary and one button. Next/Search check the fields and are never disabled.
- **D-43:** After the hero, a slim "Plan your journey" / filled-summary row docks under the sticky header. Tapping it opens the sheet at the right step.
- **D-44:** Motion: panels and the sheet fade and slide 8px over 250ms, and the bar docks over 150ms, using the motion tokens. No bounce. With reduced motion, an opacity fade only.

### Add-ons, inclusions and cart
- **D-45:** Catalog model the components serve: Colombia → 5 destinations → private stays in each destination. Experiences and services are attached to a destination or to one stay, and availability differs by place. The add-ons list shows only items available for the chosen destination and stay.
- **D-46:** Add control by unit (the unit is set in the dashboard):
  - Per person: a − n + stepper from 0 to every guest (adults + children + infants).
  - Per night: a − n + stepper from 0 to the number of nights.
  - Per trip: an "Add / ✓ Added" toggle with `aria-pressed`, counted once however long the trip.
- **D-47:** Every experience and service row has an image. The list scrolls, and the guest can add as many as they want. Filter chips (All / Experiences / Services) are 40px visible with a 44px hit area.
- **D-48:** Home pickup (a UAE service, per trip) starts added and can be removed.
- **D-49:** InclusionsList shows "Included in your journey · No extra charge", locked on, with no price. The seven inclusions are real: Airport meet, Transfer in Colombia, Your stay, Private guide, Security, Insurance, Return. They're seeded in 3.2 through the inclusions kit.
- **D-50:** JourneyCart (desktop rail) lists the stay and every add-on with its quantity and a Remove control, then subtotal, VAT [RATE]% and total, all `AED [AMOUNT]`, plus "Nothing is charged before Pay". On phone, tapping the total line opens a full-screen cart with the same content.
- **D-51:** StepRail: ✓ Stay · 2 Add-ons · 3 Travelers · 4 Pay. Square marks, a check on finished steps, a number on the others, and a teal rule under the current step.
- **D-52:** Prices are `AED [PRICE]` / `AED [AMOUNT]` and units `[per …]` until the catalog has real rates. Never invent amounts, fees or legal copy.

### Nav and logos
- **D-53:** The wordmark is used at every width, with no monogram swap on phones. The nav's large logo is the stacked charcoal lockup currently loaded from `framerusercontent.com/images/RX7lhKpzXFpv2KTvbxNSm3UZz8.svg`. It is downloaded once into `brand/Logo Typography/` as a named file and served from the repo. Every `framerusercontent.com` logo reference (nav, footer, dashboard layout, profile) moves to `brand/` files.
- **D-54:** `next.config.js` and `next.config.mjs` merge into one `next.config.ts`. Today Next only reads the `.js` file, so the SVG rule in `.mjs` never runs.

### Team
- **D-55:** TeamSection is built the way the Framer "Meet the Team" block is built (layout, photo shape, spacing), converted to Tailwind and improved where needed. It takes members as data. With zero published members, the public section renders nothing. The canvas shows the block with text-only placeholder cards (`[Name]`, `[Role]`, a monogram block).
- **D-56:** Ana Velásquez, Mateo Ríos and Sofía Marín are removed from `lib/home-copy.ts`, `lib/framer-source-copy.ts`, `components/specimens/team*.tsx` and `app/design/framer-kit.tsx` (deleted with `/design`). The Framer `route.ts` pages (`/`, `/about`, `/contact`) keep them until 3.3 and 6 replace those pages. Those files are not patched.
- **D-57:** Maria Del Mar Valdes and María Francis are real. They are removed from code and fixtures, and they appear only once published from Dashboard › Content › Team (3.2).

### Copy
- **D-58:** One shared, typed catalog at `lib/copy/`: one file per area (journey, home, guest, dashboard…), all exported through one `copy[locale]` object, with one test that fails if a key is missing in AR or ES. Journey copy goes in first, and the existing `lib/*-copy.ts` files move under it during the conversion.
- **D-59:** Contact stays `inquiries@almarprivatejourney.com` / `+971 56 388 3302`.

### /account select
- **D-60:** A named task: language and currency selects become one component that works in any parent (header, `/account`, dashboard Settings), with no parent-dependent styles. It gets a screenshot test on `/account` in EN and AR and its own UAT step.

### Claude's Discretion
- File and folder layout inside `components/`, the token-generation script, the harness setup, and how the Playwright component tests are organised.
- Keyboard model inside the panels (arrow keys in the calendar, typeahead in the destination menu), following the Radix listbox and dialog patterns already in use.
- Shadows: the bar is `shadow-float`, panels are `shadow-lg`, as on BookerKit, expressed as tokens.
