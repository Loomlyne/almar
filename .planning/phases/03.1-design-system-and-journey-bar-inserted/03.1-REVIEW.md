# Phase 03.1 code review

Scope: `git diff 8c5a75f^..31c8747`, excluding screenshots, `tests/screens` and `.planning`. Source under `app/`, `components/`, `lib/` and `scripts/` was read in full where it changed. Tests were skimmed. `npx tsc --noEmit` passes with no errors.

Checked and clean:
- **Harness gate.** `/__harness` calls `notFound()` unless `ALMAR_HARNESS === "1"`. It is `force-dynamic` and validates `c`, `s` and `l` before it renders anything. `ALMAR_HARNESS` is set only in `playwright.config.ts` `webServer.env`.
- **Production gating.** Every new dashboard and guest page calls `notFound()` in production. So do `/newsletter`, `/embed/font/[file]` and `/embed/hero-booker`.
- **Font route.** `/embed/font/[file]` only serves files on a fixed allowlist, so a crafted path cannot reach other files.
- **Security.** The changed source has no `dangerouslySetInnerHTML` and no secrets. `.mcp.json` holds URLs only. `RESEND_API_KEY` is read from the environment.
- **Prices.** No invented prices or people. Journey fixtures use `AED [PRICE]`, `[RATE]%` and `[Name]`. The USD/AED package prices in `lib/copy/home.ts` came from the live `app/route.ts`.
- **Removed routes.** No stale imports or links to `/design` or `/framer` remain in source or tests.
- **RTL.** Logical CSS (`start`/`end`, `ps`/`pe`, `inset-s`/`inset-e`, mirrored chevrons, swapped arrow keys in RTL) is correct in the journey components, Dialog, Switch and Sidebar.

No finding below is reachable in a production build, because every affected page returns 404 in production. They are still real bugs, and several break the owner rule that a control shown on screen must work end to end.

## Warning

### W1. Dashboard phone menu: focus is lost on close, and the Close button is outside the Tab loop
`app/dashboard/(ops)/layout.tsx:116-124`, `:222-246`

- **What is wrong:** `menuButtonRef` is attached only to the hamburger button, and that button is unmounted while the menu is open (`menuOpen ? <close button> : <hamburger ref=...>`). When Escape or the Close button runs `menuButtonRef.current?.focus()`, the ref is `null`, so nothing gets focus. The element that had focus (a link inside the nav) then becomes `hidden`. Separately, the Tab trap only collects focusable elements inside `<nav id={menuId}>`. The Close button sits in the `<header>`, outside that set.
- **Failure scenario:**
  1. A keyboard user at 1024px opens the menu, Tabs to "Stays", and presses Escape.
  2. The menu closes and focus drops to `<body>`, so the next Tab starts from the top of the page.
  3. While the menu is open, Tab and Shift+Tab cycle through the nav links but never reach the Close button.
- **Fix:**
  - Keep one toggle button mounted, with the ref, `aria-expanded={menuOpen}` and a label that switches between Menu and Close.
  - Move focus back in a `useEffect` that runs after `menuOpen` becomes false.
  - Add the header toggle to the set of elements the Tab trap cycles through.

### W2. Site nav phone menu: focus is not restored, and Escape in the language or currency list also closes the whole menu
`components/ui/nav.tsx:92-95`, `:117-123`

- **What is wrong (focus):** `closeMenu()` calls `setOpen(false)` and then, in the same tick, `menuRef.current.focus()`. At that moment the Menu button still has the `hidden` class (the re-render has not run yet), so `focus()` on a `display:none` element does nothing. The Escape handler has the same problem.
- **What is wrong (Escape):** the document `keydown` handler does not check `event.defaultPrevented`. Radix Select handles Escape in the capture phase and calls `preventDefault()`, but this handler closes the menu anyway.
- **Failure scenario:**
  1. On /account at 375px, the user opens Menu and then opens the Language list.
  2. Pressing Escape closes both the list and the whole menu.
  3. Focus lands on `<body>`.
- **Fix:**
  - Add `if (event.defaultPrevented) return;` at the top of `onKey`. `hero-booker.tsx:256` already does this.
  - Restore focus in an effect after `open` becomes false.

### W3. Stepper disables the button the user just pressed, so keyboard focus is lost
`components/ui/stepper.tsx:46-66`

- **What is wrong:** reaching `min` or `max` sets `disabled` on the button that has focus. The browser then drops focus to `<body>`.
- **Where it shows up:** GuestPanel (Adults 2 to 1, Children 1 to 0), AddOnRow per-person and per-night steppers at their cap, and the HeroBooker guest rows.
- **Failure scenario:**
  1. In the Guests panel, a keyboard user presses "Remove adult" when Adults is 2.
  2. The count goes to 1 and the button disables.
  3. Focus is gone, so the next Tab starts at the top of the document, outside the popover.
- **Fix:** at the bounds, use `aria-disabled="true"` plus an onClick guard instead of `disabled`. Alternatively, move focus to the opposite button when the bound is reached.

### W4. Hero booker calendar loses its only Tab stop after month navigation
`components/ui/calendar.tsx:80-81`, `:132-147`

- **What is wrong:** `tabDay` is `focused ?? start ?? now`, and there is no check that this date is in the month currently shown. After "Next month" is clicked, no day button has `tabIndex=0`, so the whole grid drops out of the Tab order. The "Previous month" button is also never disabled, so the user can page into past months where every day is disabled.
- **Failure scenario:**
  1. The user opens Dates and clicks Next month.
  2. Tab goes from the Next button straight to "Clear dates". No date can be reached by keyboard.
- **Fix:** do what `DateRangePanel` does at `components/journey/date-range-panel.tsx:127-130`. If `tabDay` is not in the shown month, use the first selectable day of that month. Also disable Previous at the current month.

### W5. Media URL and Photo URL fields cannot be typed into
`app/dashboard/(ops)/catalog/catalog-screen.tsx:64-74`, `app/dashboard/(ops)/content/content-screen.tsx:61-71`

- **What is wrong:** the controlled input only stores a value that is empty or already starts with `https://`. Any partial value such as `h`, `ht` or `https:/` is thrown away, and the input snaps back to empty.
- **Failure scenario:** in Catalog > Stays > New stay, the user types `https://cdn...` one key at a time. The first key `h` is rejected, the field stays empty and shows "Enter a URL that starts with https://.". Only pasting a full URL works.
- **Fix:** store every keystroke. Validate on blur or submit (or when the value is not a prefix of `https://`). Keep the "never stored or uploaded unless https" guarantee at the save point, not on each keystroke.

### W6. Controls are shown that do nothing (owner rule)
Every page here is dev-only, but each one shows a working-looking control with no effect:

| Control | Location | What happens |
|---|---|---|
| Settings Save | `app/dashboard/(ops)/settings/settings-screen.tsx:104` | `onClick={() => undefined}`. The VAT, deposit, email, logo and maintenance values are never saved. |
| Catalog Publish | `catalog-screen.tsx:140` | `onClick={() => undefined}` |
| Content Publish | `content-screen.tsx:94` | `onClick={() => undefined}` |

### W7. Nav links and currency select on the new guest pages lead nowhere
`components/ui/nav.tsx:52`, `:74-79`, `:227-234`

- **What is wrong:**
  - The Destinations, Experiences, About and Contact links point to `#destinations`, `#experiences`, `#about` and `#contact`. None of those ids exist on `/account`, `/bookings`, `/login` or `/booking/trip`.
  - Login defaults to `#log-in` on `/account`, `/bookings` and `/login` (only the trip page passes `loginHref="/login"`).
  - The logo is labelled "ALMAR Private Journeys home" but links to `#content`.
  - The currency select only changes its own label. No caller passes `onCurrency`, and these pages show no prices.
  - The hrefs come from before this phase, but this phase ships them on three new pages.
- **Failure scenario:** on /bookings, clicking "About" or "Login" does nothing.
- **Fix:** link to the real routes (`/destinations`, `/about`, `/contact`, `/login`, and `/` for the logo). Hide the currency select on pages without prices until it drives something.

### W8. The chosen language is not restored on guest pages
`app/account/account-screen.tsx:87`, `app/bookings/bookings-screen.tsx:147`, `app/login/sign-in-screen.tsx:207` (and `app/booking/trip/trip-screen.tsx:58`, which predates this phase)

- **What is wrong:** `LocaleSelect` writes the `almar-locale` cookie, but these screens always start at `"en"` and never read it. The dashboard does read it, through `readLocale()`.
- **Failure scenario:** the user picks العربية on /account and then opens /bookings or reloads /account. The page is back in English, LTR, with the selector showing EN.
- **Fix:** read the cookie on mount (the same `readLocale()` helper the dashboard uses, ideally moved to `lib/set-document-locale.ts`). Then call `setDocumentLocale`.

### W9. Footer newsletter reports success without sending anything
`components/ui/footer.tsx:22`

- **What is wrong:** a valid email triggers `push("Subscribed. Check your inbox.")` with no request. `/newsletter` also returns 404 in production.
- **Current reach:** `SiteFooter` is not mounted on any page today, so nobody can hit this yet.
- **Failure scenario:** once the footer is wired into a page, every visitor who subscribes is told it worked, and no contact is ever created.
- **Fix:** POST to a working endpoint and show the toast only on `ok: true`. Until then, do not render the form.

## Info

### I1. The harness bundles test code into the app build
`app/%5F%5Fharness/harness-client.tsx:5-6`, `:20`

`harness-client.tsx` imports `tests/journey/fixtures` at the top of the module. Its template `import()` also pulls every file in `tests/journey/scenes/` into client chunks.

- The page gate works: without `ALMAR_HARNESS=1` the route 404s.
- The Cloudflare assemble step copies only `.body` files, so these chunks are not deployed there.
- Under `next start` or Vercel (`vercel.json` exists), the chunks would be publicly fetchable under `/_next/static`.
- `tests/harness-gate.test.mjs` only checks `page.tsx`, so it does not catch this.

**Fix:** exclude the folder from production builds (for example, `pageExtensions` or a build-time env switch). Alternatively, extend the test to cover `harness-client.tsx`.

### I2. Dead code left by the /design and /framer removal and the class-hook cleanup
- `app/dashboard/(ops)/layout.tsx:264`: a `<Sidebar open={false} onOpenChange={() => undefined}>` that can never open.
- `app/dashboard/(ops)/layout.tsx:91-99`: sets `data-density="compact"` on `<html>`. The only density variant in CSS is `dense`, so this attribute does nothing.
- `lib/copy/framer-source.ts`: its only consumer was the removed `app/framer/source/route.ts`. It survives only through the re-export in `lib/copy/index.ts`, which drags it into the harness bundle.
- `components/ui/checkbox.tsx` and `components/ui/footer.tsx` are imported by no page.
- `components/specimens/hero-booker.tsx:89`: `GUEST_ROWS` is unused. It predates this phase.
- Class hooks `ui-button`, `ui-button-primary`, `ui-chip`, `is-on`, `is-muted`, `ui-input`, `field*`, `choice*`, `switch`, `calendar` and `ui-link` no longer have rules in `app/globals.css`. The comments saying they are kept "for legacy rules" are out of date.

### I3. ARIA grid misuse
- `components/ui/calendar.tsx`: `role="gridcell"` buttons sit directly inside `role="grid"`, with no `role="row"`.
- `app/dashboard/(ops)/calendar/calendar-screen.tsx:249`: `role="grid"` with no rows and no arrow-key navigation, so every day (up to 31) is a separate Tab stop.

**Fix:** add rows and roving focus, or drop the grid role and use a plain list of buttons.

The root layout (`app/layout.tsx`) and `app/dashboard/(ops)/layout.tsx:209-214` both render a "skip to content" link to `#content`. Keyboard users meet two in a row. Keep one.

`settings-screen.tsx:12-22` copies the colour values from `tokens.json` and labels them "the real tokens". They will drift silently when tokens change. Read them from `tokens.json`, or say plainly in the label that they are a copy.
