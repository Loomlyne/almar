# Phase 3.2 Plan 01: Catalogue and team database Summary

**Catalogue, rates, availability and team move into Postgres: one migration (21 tables, 14 anon-safe views, 43 service-role functions) proven on a per-worktree local stack with 252 pgTAP assertions, plus the owner gate and a dry-run-first fixture import.**

## Accomplishments

- The migration applies from empty on a local stack after job 02's migration. btree_gist is available (default 1.7), so `stay_rates` refuses overlapping same-length ranges with SQLSTATE 23P01 through `exclude using gist (stay_id with =, span_days with =, nights with &&)`.
- RLS is on all 21 tables. `anon` has no table privilege except column-level `select` on published columns, and a picture, its alt text and a blocked-days row are public only when they follow a published parent (see Review fixes); `stay_access`, `stay_rates`, `team_members.email`, `availability_blocks.reason`, `stays.base_nightly_rate_aed` and `stays.pets_fee_aed` cannot be selected at all. Insert, update, delete and RPC execute fail for anon.
- The ops functions (`ops_save_*`, `ops_delete`, `ops_reorder`, `ops_publish`, `ops_list`, `ops_get`, rates, blocks, access, media) implement contract §5: absent key untouched, join sets replaced only when present, `almar:parent_unpublished` on moving a published stay under an unpublished destination, `ops_publish` refuses unless every EN text is filled in AR and ES.
- `requireOwner()` answers `not_owner` unless the request is on the ops host and the session profile passes `isOwnerProfile`; `unavailable` when the service-role client cannot be made; never `getSession`.
- `scripts/import-catalog.mjs` builds the payload offline from the fixtures. With no flag it touches no network and prints a per-table count and every skipped value.
- `tests/helpers/local-supabase.mjs` gives every worktree its own stack (project_id and port block derived from the worktree path) with `start|reset|test|status|stop|types`, and `ALMAR_REQUIRE_STACK=1` turns a missing stack into a failure instead of a skip.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Pets constraint let "fee with no fee amount" through**
- **Found during:** Task 1 pgTAP
- **Issue:** a CHECK passes on NULL, so `pets_rule = 'fee'` with `pets_fee_aed` null was accepted.
- **Fix:** CASE expression: null rule needs null fee, `'fee'` needs a fee, any other rule needs null fee.
- **Files:** `supabase/migrations/20261005100000_catalog_and_team.sql`
- **Commit:** `6e55c38`

**2. [Rule 1 - Bug] Partial update of an existing translation died on NOT NULL**
- **Found during:** Task 1 pgTAP, `ops_save_*` with a translation record that omitted `name`, `title` or `price_label`
- **Issue:** the INSERT row is checked before ON CONFLICT, so an absent required column failed even though the stored row held a value.
- **Fix:** `catalog_save_translations` coalesces a required column with the stored value when the key is absent.
- **Commit:** `9d217ae`

**3. [Rule 3 - Blocking] Phase-02 key-material gate refused the generated types**
- **Found during:** Task 2 full suite
- **Issue:** `lib/supabase/database.types.ts contains re_` from the parameter `p_require_en`.
- **Fix:** renamed to `p_need_en`, types regenerated (never hand-edited).
- **Commit:** `5ead3b6`

**4. [Rule 1 - Bug] `api_site_version` referenced a column anon cannot read**
- **Fix:** selects `requested_seq` with `limit 1`.
- **Commit:** `6e55c38`
