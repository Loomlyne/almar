<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Owner click → deploy hook | The hook URL is a bearer credential: whoever holds it can start builds |
| Workers Builds → live Worker `almar` | Builds whatever `live` holds; content from the database |
| GitHub `live` branch → production | Code path to the live site |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|---|---|---|---|---|
| T-3.2-27 | Elevation | Code shipped by a Publish click | mitigate | Builds only from `live` (Workers Builds setting + `build-live.mjs` branch guard); `live` moved only by the controller on the owner's word |
| T-3.2-28 | Information disclosure / DoS | Deploy hook URL leak | mitigate | Secret on almar-ops only, never logged or returned; Cloudflare's 10 builds/min cap; owner can delete and recreate the hook |
| T-3.2-29 | Tampering | A broken or partial build replacing the live site | mitigate | `build-live.mjs` fails closed before the deploy command; 03.2-02 refuses a fixture fall back and empty data |
| T-3.2-30 | Spoofing | Status line showing "Up to date" falsely | mitigate | Truth is `site-version.json` from the live host, no-store; no cached or client-made state |
| T-3.2-31 | Elevation | Builds API token in a Worker | mitigate | Not used at all (research §1.1: it would need Edit rights); status is computed from the sequence |
| T-3.2-32 | Denial of service | Many clicks exhausting build minutes | accept | Settle window collapses bursts to ≤ 2 builds; ~375-500 publishes a month fit the Free 3,000 minutes (research §1.3) |
</threat_model>
