## Migration `20261015120000_stay_access_notes_i18n.sql`
- `alter table public.stay_access add column notes_ar text check (char_length(notes_ar) <= 2000), add column notes_es
  text check (char_length(notes_es) <= 2000);` and `create or replace function public.ops_save_stay_access(p jsonb)`
  with the same signature, `search_path = ''` and security; it only adds the two notes (absent = untouched, empty =
  null). Ends with the revoke from public/anon/authenticated and grant to service_role (repeats the ACL already in
  place; kept on the controller's word).
- **Safe on live rows:** additive. Two nullable columns, no default, no backfill, no rewrite; existing rows read null
  for both. No grant, policy or view: `stay_access` stays closed to anon and authenticated (C-14). No existing row is
  changed.
- **Order at landing:** apply it live **before** deploying `almar-ops`. The new GET selects `notes_ar, notes_es`; on a
  database without the columns the Access card would fail to load.
- Not applied anywhere but local stacks. The controller applies it at landing after a second-model check.

   "Range" price inside the range, "Base" price outside.

9. In Availability, move to a month with a block from the Calendar. Expected: those days marked "Blocked" and the reason
