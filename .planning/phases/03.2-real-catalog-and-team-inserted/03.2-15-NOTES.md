## Rate rules (C-11, C-12), as the database already enforces them (`20261005100000_catalog_and_team.sql`)
1. One base nightly rate per stay, AED, `numeric(12, 2)`, > 0, or none. **No base rate = the stay cannot be booked**
   (`bookable = is_published and base_nightly_rate_aed is not null`).
2. Any number of date ranges per stay, each with its own nightly rate (> 0); first and last night inclusive; at most 730
   nights. Stored as `daterange(first, last + 1)`.
3. A night's price: the **shortest** range covering it (`order by span_days, id limit 1` in `stay_night_rates`), else the
   base rate, else no price.
4. Two ranges of the **same length** can never share a night: exclusion constraint `stay_rates_same_length_no_overlap`
   → API 409 `rate_overlap` with `detail.conflict_id`; the tab marks that row and keeps what was typed.
5. Rates are read live, never baked: a rate change never triggers a site rebuild (`affects_site: false`, C-04).
6. The screen never computes a total; "Check prices" lists each night's price and its source (range / base / no rate)
   from the API (max 366 nights).

## Data shape (contract §5.3–5.5, types already in `components/ops/api-types.ts`)
- Money: AED decimal **string**, 2 decimals, `"1250.00"`; `null` = not set. Never a float.
- `GET /api/ops/stay-rates?stay_id=` → `{ base_nightly_rate_aed, ranges: [{ id, first_night, last_night, nights, nightly_rate_aed }] }`;
  with `&from=&to=` (nights `[from, to)`) adds `nights: [{ night, nightly_rate_aed, source }]`.
- POST `set_base` / `save_range` / `delete_range`.
- `GET /api/ops/blocks?from=&to=&stay_id=` (inclusive days, window ≤ 400) → this stay's, its destination's and
  all-scope blocks.
- `GET|POST /api/ops/stay-access` → `{ address, wifi_name, wifi_password, door_code, notes }`, each ≤ 2,000 chars,
  null allowed; password and door code kept exactly as typed; never logged; no public view.
