## Summary

The fixture contract from 3.3 is well suited to a mechanical swap: every `lib/data` module reads base rows plus one
translation record per locale with `readFixture(name)` and resolves them with `resolveRow` / `image`
(`lib/data/resolve.ts:16-114` on `gsd/phase-3.3-s1-framer-match`). The cleanest swap is **anon-readable Supabase
views that return exactly the fixture JSON shapes** (`api_stays` returns rows shaped like `stays.json`, including
nested `hero_image` / `gallery` objects and `experience_ids`), so each module changes only its read function and
`resolveRow` / `resolveImage` stay untouched. A node parity test then compares fixture-mode and Supabase-mode reads
for every export in all three locales, and a build diff proves the HTML is byte-identical. The diff is against a
"live-shaped" fixture set, because C-16 drops the sample blocked dates, so the stay pages' sample-dates note
disappears on purpose.

For Publish, use **Cloudflare Workers Builds connected to `Loomlyne/almar`, production branch `live`, plus a
Deploy Hook**. Deploy Hooks exist since 2026-04-01. They are a POST with no auth header, and Cloudflare skips a
second build while one is still queued. With the Free plan's one concurrent build and a 120 s settle sleep at the
start of the build command, a burst of clicks gives at most two builds, usually one, with no cron, Durable Object
or extra state. The dashboard learns the status by comparing a `requested_seq` in Supabase with a
`site-version.json` the build writes into `out/`. The Builds API needs a user-scoped token with *Edit* on
builds, which is too much power to keep in a Worker. A GitHub Actions `workflow_dispatch` route works too, but it
needs a Cloudflare token stored in GitHub and a GitHub PAT stored in the Worker. It is rejected.

**Blocking cross-job finding (read first): in job 02's current design no dashboard page can be reached in
production.** The dashboard lives only on the ops host `dashboard.almarprivatejourney.com` (`lib/host.ts:3,51-60`).
Plan 02-23 keeps `/dashboard` held and says "the ops host is not on Worker `almar` (owner gate 6, later)"
(`02-23-PLAN.md` Task 3). Job 10's `run_worker_first` matches the URL path only, never the host. So an ops-host
request for `/` would get the marketing `out/index.html` from the static layer, and `/catalog/stays` would get the
static 404 without the Worker ever running. 3.2 cannot ship a wired dashboard until the controller and owner
choose how the ops host is served. The recommendation is a second Worker `almar-ops` that holds every owner-power
binding and secret (Open Question 1).

**Primary recommendation:** views shaped like the fixtures + a `readSource()` swap inside `lib/data`; Workers
Builds + Deploy Hook on branch `live` with a settle sleep; `@cf/google/gemma-4-26b-a4b-it` as the translation
candidate, chosen only after the 3-text Arabic spike; R2 uploads keyed by a content hash through an owner-only
`/api/ops/media`; all owner-power bindings on an ops Worker, so the public Worker `almar` stays binding-free.

### 1.3 Recommended design: Workers Builds + Deploy Hook + settle sleep

```
Owner clicks Publish (ops host)
  → POST /api/ops/publish  (requireOwner, Origin check)
      1. the entity RPC has already saved the content
      2. rpc site_request_update(): site_publish.requested_seq += 1, requested_at = now()  (service role)
      3. fetch(PUBLISH_DEPLOY_HOOK_URL, {method:"POST"}) → store build_uuid / already_exists / error
  → Workers Builds (branch live): queued → running
      build command: node scripts/build-live.mjs
        a. sleep ALMAR_PUBLISH_SETTLE_SECONDS (120)      ← clicks in this window are included
        b. read api_site_version.requested_seq (anon)   ← read BEFORE any content
        c. node scripts/assemble-cloudflare.mjs --target=production  (lib/data reads anon views)
        d. write out/site-version.json {seq, built_at, commit}
      deploy command: npx wrangler deploy --config wrangler.toml
  → fail at any step = no deploy = live site unchanged (C-03)
Dashboard polls GET /api/ops/site-status every 15 s while "Updating"
  requested_seq (DB)  vs  live seq (GET https://almarprivatejourney.com/site-version.json, no-store)
```

**Debounce, proven by the documented semantics:** click 1 → build B1 (running, sleeping). Clicks during B1 → the
first one creates B2 (queued, because the Free plan allows one concurrent build); later ones return
`already_exists` while B2 is queued. B1 reads content after its 120 s sleep; B2 picks up everything after that.
So a burst gives **at most two builds, usually one**. No cron, Durable Object or queue is needed (Workers Free
stays). Window = settle seconds; the planner sets 120 (C-03 asks for about 2–5 min).

Budget: about 2 min sleep + about 4–6 min install and build [ASSUMED, measure] ≈ 6–8 min per publish → roughly
375–500 publishes a month inside 3,000 free minutes.

**Status rules (`/api/ops/site-status`):**
- `Up to date (time)`: live `seq ≥ requested_seq`; show `built_at`.
- `Updating (since time)`: live `seq < requested_seq` and `now − requested_at < 28 min` (20 min build timeout + settle + deploy margin).
- `Update failed (time)`: the hook POST failed, or 28 min passed with live still behind. Show **Try again**, which
  re-fires the hook (a shown control must work). The owner opens the build log in the Cloudflare dashboard. No
  Builds-API token is stored in a Worker (it would need Edit rights; §1.1).
- `site-version.json` must be served `Cache-Control: no-store`: add a rule in `writeTargetFiles` (`scripts/crawl-files.mjs`, `_headers`).

## 3. R2 upload through the Worker (C-10)

### 3.1 Facts

- `put(key, ReadableStream | ArrayBuffer | … , { httpMetadata, customMetadata, onlyIf, sha256 | md5 … })`;
  with a failed `onlyIf`, `put` returns null and stores nothing; the integrity hash is checked by R2
  [CITED: developers.cloudflare.com/r2/api/workers/workers-api-reference/]. Binding: `[[r2_buckets]] binding = "MEDIA"`, `bucket_name = "almar-media"`.
- Request body limit **100 MB on Free/Pro**; 10 ms CPU on Free; 50 subrequests; 100,000 requests a day; 128 MB memory
  [CITED: developers.cloudflare.com/workers/platform/limits/].
- Bucket `almar-media` and `media.almarprivatejourney.com` are live; 117 objects uploaded on 2026-10-03
  (CONTROL-BOARD). The job 11 manifest now has **118** entries with 118 image ids, one id per key
  (`lib/data/media-manifest.json` on `835d7b4`: catalog 10, destinations 4, home 22, stays 82). The controller
  confirms all 118 are in the bucket (`node scripts/media-upload.mjs --verify --all`) before the import.
- Safari cannot encode WebP from canvas; it silently returns PNG [CITED: dev.to article above; caniuse search].

### 3.2 Design

- **Browser:** pick a file (`accept="image/jpeg,image/png,image/webp"`); scale to at most 2560 px on the long edge on a
  canvas; encode WebP if `blob.type === "image/webp"` after a probe, else JPEG 0.85; compute SHA-256 with
  `crypto.subtle`; read the width and height. iPhone HEIC → JPEG when the accept list excludes HEIC is [ASSUMED]:
  test on his phone at UAT.
- **`PUT /api/ops/media`** (raw body, not multipart): `requireOwner()`, Origin = ops origin, `Content-Type` in
  {webp, jpeg, png}, `Content-Length` ≤ 15 MB (our cap), header `x-almar-sha256` (64 hex), width and height 1..10000.
  Key = `uploads/<first 32 hex of sha256>.<webp|jpg|png>`: content-addressed, so the same file gives the same key and
  nothing is ever overwritten (one-year immutable cache, as `scripts/media-lib.mjs` `CACHE_CONTROL`). `MEDIA.head(key)` →
  if present skip, else `MEDIA.put(key, request.body, { httpMetadata: { contentType, cacheControl }, sha256 })`.
  Then the RPC inserts the `media` row (+ EN alt required; AR/ES through Translate).
- **Key rules:** `mediaUrl()` already refuses `://`, `..`, a leading `/`, `\` (`lib/data/media.ts:16-27`). The
  scripts' `KEY_RE` allows only `.webp` (`scripts/media-lib.mjs` `KEY_RE`): widen it to `\.(webp|jpg|png)$` or leave
  the scripts untouched (they serve the fixture images only). The DB check constraint holds the rule for uploads.
- **CPU risk:** OpenNext may buffer the request body into a Node stream before the route handler runs [ASSUMED].
  Measure a 10 MB upload on preview with `wrangler tail`. If it goes over 10 ms, serve this one path in the Worker
  wrapper before Next, with the same owner check.
- **Picking existing photos:** the `media` table is seeded with all 118 manifest entries (§4.6). The picker lists
  `media` rows; choosing one stores its id. Alt text is per image (C-10), so a photo reused elsewhere keeps its alt.
- Deleting media: v1 deletes only the DB row when nothing references it (FKs `on delete restrict`); the R2 object
  stays (immutable, cheap). Say so on the screen.

## Common Pitfalls

1. **Free plan 10 ms CPU on dashboard SSR.** React server rendering of a dense table page through OpenNext is
   likely to exceed 10 ms of CPU [ASSUMED; job 10 measured only `/api/health`]. Wave 0: deploy one wired list
   screen to preview, run it 20 times with `wrangler tail`; any `exceededCpu` → the owner's upgrade question
   (D-SR-02 rule). Keep list pages lean: one RPC returning JSON, paginate nothing (12 stays).
2. **A silent fall back to fixtures in production** would ship sample data. The source must be explicit and assembled
   builds must refuse it (§5.1).
3. **Manual deploy overwritten by the next Publish** (§1.4). Rollback must move `live` too.
4. **Service key reaching the build or a client.** `tests/secrets.test.mjs` scans `app`, `components`, `lib`,
   `middleware.ts` only (`:15`). Extend it to `scripts/` and `worker/`; allow `SUPABASE_SERVICE_ROLE_KEY` only in
   `lib/supabase/clients.ts` and `scripts/import-catalog.mjs`; assert `lib/data/**` never imports
   `lib/supabase/clients` and never names the service key; assert no `NEXT_PUBLIC_*SERVICE*` (exists, `:22-25`).
5. **Security-definer views** bypass RLS (lint 0010 ERROR). Use `security_invoker = on` (§4.1). Supabase also grants
   ALL on new views by default (job 02's own comment, `platform_spine.sql:115-118`): revoke, then grant select.
6. **PostgREST row cap.** Supabase returns at most 1,000 rows per request by default [ASSUMED default]:
   `api_image_translations` is 354 rows today, `api_stay_blocked_days` can grow. Aggregate in the view (arrays) or
   page through with `.range()`; the parity test must fail on truncation (counts).
7. **Amenity count mismatch** (`stays.ts:74-76`) after a translation or an edit breaks the build. The RPC refuses

const VIEWS = { stays: "api_stays", "stay-translations": "api_stay_translations", /* … one per fixture */ } as const;

export function dataSource(): "supabase" | "fixtures" {
  return process.env.ALMAR_DATA_SOURCE === "supabase" ? "supabase" : "fixtures";
}
export async function loadSource(): Promise<void> {
  if (dataSource() === "fixtures") return;
  loaded ??= (async () => {
    const url = process.env.NEXT_PUBLIC_SUPABASE_URL, key = process.env.NEXT_PUBLIC_SUPABASE_ANON_KEY;
    if (!url || !key) throw new Error("ALMAR_DATA_SOURCE=supabase without the public Supabase settings");
    const db = createClient(url, key, { auth: { persistSession: false, autoRefreshToken: false } });
    const out = new Map<string, unknown>();
    for (const [name, view] of Object.entries(VIEWS)) {
      const { data, error } = await db.from(view).select("*");
      if (error) throw new Error(`${view}: ${error.message}`); // the build fails; the live site stays
      out.set(name, data);
    }
    return out;
  })();
  await loaded;
}

## Security Domain

| ASVS | Applies | Control |
|---|---|---|
| V2 Authentication | yes (inherited) | Job 02 magic link + owner role and email (`isOwnerProfile`) |
| V3 Session | yes (inherited) | `getUser()` on every call, never `getSession` (`clients.ts:56-61`) |
| V4 Access control | **yes** | `requireOwner()` first line of every `/api/ops/*`; RPC execute only to `service_role`; RLS + invoker views for anon |
| V5 Input validation | yes | Plain TS validators (house style, `lib/auth/rules.ts`); DB checks mirror them (widen in SQL, never narrow the app) |
| V6 Cryptography | limited | SHA-256 via `crypto.subtle` and R2 integrity; no custom crypto |
| V12 Files | yes | Type allow-list, size cap, content-addressed keys, immutable, no overwrite, served from the media host only |
| V13 API | yes | Origin check on every state-changing call (CSRF); JSON only; `x-robots-tag: noindex` (wrapper) |

| Threat | STRIDE | Mitigation |
|---|---|---|
| Non-owner calls `/api/ops/*` | Elevation | `requireOwner` per call + test that enumerates routes |
| Cross-site POST from another tab | Tampering | Origin = ops origin; SameSite cookies (job 02) |
| Anon reads stay access, rates or drafts | Info disclosure | No grants; RLS published-only; SQL tests as the `anon` role |
| Deploy hook URL leaks | DoS / cost | Worker secret only; 10/min limit at Cloudflare; owner can rotate (delete and recreate the hook) |
| AI output injected into pages | Tampering | Text only, rendered by React (escaped); owner review (draft status) |
| Upload of a non-image | Tampering | Type allow-list + R2 `contentType` fixed by the server; browser re-encodes |
| Service key in a bundle | Info disclosure | Extended `secrets.test.mjs`; assembler `assertNoBundledEnv`; key only on the ops Worker |
