Two runs were red during the work. Each was fixed and rerun, and both runs are reported here:

1. First full serial node run with the stack: **1302 / 1287 pass / 2 fail**. One `ops-api-local` call came back 503 with no SQLSTATE. Repeating `import-catalog` and `ops-api-local` serially failed 3 of 4 times, and `import-catalog` failed as well: "Could not find the function public.import_catalog(p) in the schema cache". The cause is `supabase db reset`, which restarts the database container, and PostgREST needs seconds to reload its schema cache and pool. Commit 6 fixed it: the local test now waits for 15 good calls in a row before the import and after its final reset. After the fix, 5 of 5 repeats were green and the full serial run had 0 failures.
2. First owner-session run of the built-Worker spec: B2 got 403 `wrong_origin` where 415 was expected. A temporary debug route, never committed, showed what Next received: `Origin: http://dashboard.almarprivatejourney.com` instead of the `https` Origin that was sent. Local `wrangler dev`'s ProxyWorker rewrites every header that names the request host to the scheme of the URL the Worker sees, which is `http` by default (`rewriteUrlRelatedHeaders`). The fix is local only: the stack copy of the config sets `[dev] upstream_protocol = "https"`, so `request.url` and `Origin` match the edge. The production code was not changed.

### Interpretations (stated so the controller can overrule)

- **Status of `almar:invalid`.** A refusal raised by the database is 409 `invalid` with the field: an unknown photo id, a published slug, a language record created without its required name. The route's own parse is 400. The contract only named 409 for the slug and the home pickup; the rule is written in contract 4.1.
- **Journey save.** The plan said "save requires … EN name and price_label". As built, `translations.en`, when sent, must carry both, and the price is re-derived from them. A save without EN, such as `{id, is_featured}`, is allowed and leaves the price columns alone, so they always agree with the stored label. Each price part parses on its own, as `lib/data/types.ts` allows.
- **`api-types.ts`.** The plan listed `Locale`, `TranslationStatus` and `ApiError`. They exist on main as `Locale3`, `TextStatus` and `OpsError` (03.2-11) and were imported, not recreated. Only the missing reply types were added.
- **Unknown keys are refused** everywhere in a body, which is stricter than the database (it ignores them). `is_published` and `position` are refused in a save.
- **Caps** sit above the longest imported text. `price_note` (120 characters today) is a paragraph (4,000); the labels cap at 120; names and amenity items cap at 160.
