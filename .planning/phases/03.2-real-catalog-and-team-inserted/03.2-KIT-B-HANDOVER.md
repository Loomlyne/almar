## What changed, by point of the prompt

1. **Full-page editor (B).** New `components/ops/edit-page.tsx` (`EditPage`): it replaces the list (the list stays mounted
   behind it, hidden, so search and scroll survive), with a back link named after the list. Top bar: title (h1, focused on
   open), Published/Draft chip, a status line (Adding Arabic and Spanish… / Unsaved changes / Arabic and Spanish updated),
   Save (outlined, the design-system `secondary` button) and Publish (teal fill, ivory text, the `primary` button). A
   published item shows Save and update site (+ Unpublish when the screen has one). Sections are cards: the screen gives
   each `column: "main" | "side"`; from `lg` they sit in two columns (main spans 2 of 3), one column below. Delete is a
   text link (error colour, underlined) under the side column, with its note. Square corners, gold only as lines, tokens
   only, no arbitrary values, logical sides only. Guard: back link and Escape ask "Discard changes?" when dirty (Escape is
   ignored while a dialog or popup is open), the browser asks before the tab is closed, focus returns to the row that
   opened the page (or the list heading when that row is gone). Every field is disabled while a Save runs.
   `publish-bar.tsx` is now the top bar's buttons and notes (two parts sharing ids); Delete left it.
2. **Automatic translation.** New pure `components/ops/auto-translate.ts`. On Save the page asks `POST /api/ops/translate`
   (03.2-10, unchanged) per target, only for English fields that changed or whose Arabic/Spanish is empty, never over a
   translation Maria typed herself; 45 s timeout per request. Results go to the screen's `onSave(payload, intent)`.
   A field that did not come back (failed target, `left`, longer than the field's `maxLength`) is saved empty, Publish is
   disabled (its `aria-describedby` names the alert) and an alert says why: failed, daily limit (resets 04:00 Dubai), or
   busy. On a published item a failed translation saves nothing ("the site is unchanged"). Save stays live after a failure
   to try again. Publish with unsaved work saves, translates and publishes in one `onSave(…, "publish")`; if the
   translation fails it saves without publishing. "Edit translations" opens the Arabic and Spanish boxes (lang/dir set).
   **Deleted** (no other user): `components/ops/locale-tabs.tsx`, `tab-list.tsx`, `translate-button.tsx`,
   `edit-panel.tsx`, `lib/copy/ops-translate.ts`, scenes `ops-translate.tsx`, `ops-translate-live.tsx`,
   `tests/ops-translate.spec.ts` (and the button/copy tests in `tests/ops-translate.test.mjs`; the route tests stay).
3. **Copy** (`lib/copy/ops-kit.ts`, the one shared copy file the prompt allows). New group `editor` in EN/AR/ES. Taken
   verbatim from 03.2-06's `panel` drafts (`ca93e52`): section titles, englishOnly, translationsUpdated, editTranslations,
   hideTranslations, translationsNote, translationFailed, unsaved. **New drafts, owner to review:** `translating`,
   `translationLimit`, `translationBusy`, `translationFailedLive`, `fields.alt` ("alt text"), and `errors.not_found`
   reworded for a page ("Go back to the list and refresh it", was "Close the panel…"). Every Spanish string of the file
   is now usted (e.g. "Primero deje de publicarlo", "Revise {field} e inténtelo de nuevo."). Removed (only the tabs and
   chips used them): `draftNote`, `missing`, `checkedTranslation`, `languageTabs`, `sections`. No price, rate or legal text.
4. **Media library** is on the new editor: title = file name; main card "Alt text" (English only, required, 300 max);
   side card "Photo" (image, where it is used); Delete image link with its note. A photo is Published when EN, AR and ES
