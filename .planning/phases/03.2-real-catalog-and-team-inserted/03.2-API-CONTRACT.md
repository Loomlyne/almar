### 1.1 Response envelope

Success:

```json
{ "ok": true, "...": "endpoint fields" }
```

Every write also returns `"id"` and `"affects_site": true | false` (the change reaches the public site, which is
baked at build). After 03.2-05 lands, a write with `affects_site: true` also returns
`"site": SiteStatus` (§6) because the helper has requested a rebuild.

Error:

```json
{ "ok": false, "error": { "code": "slug_taken", "field": "slug", "locale": null, "detail": null } }
```

| HTTP | `code` | When |
|---|---|---|
| 400 | `invalid` | Validation failed; `field` names the first bad field (dotted path: `translations.ar.title`, `range.first_night`), `locale` set when the field is per language |
| 403 | `not_owner` | No session, or the session is not the owner (`isOwnerProfile`), or the request is not on the ops host |
| 403 | `wrong_origin` | POST/PUT from another origin |
| 404 | `not_found` | Unknown id |
| 409 | `slug_taken` | Unique slug (SQLSTATE 23505); a 23505 on `catalog_items_one_home_pickup` maps to 409 `invalid` field `is_home_pickup` |
| 409 | `rate_overlap` | Same-length rate range shares a night (SQLSTATE 23P01); `detail.conflict_id` |
| 409 | `in_use` | Delete refused by a foreign key (23503), e.g. a destination with stays, a photo still used |
| 409 | `published` | Delete of a published row: unpublish first |
| 409 | `publish_incomplete` | Publish refused; `detail.missing: [{ "locale": "ar", "field": "title" }, …]` |
| 409 | `has_published_stays` | Unpublish of a destination that still has published stays |
| 409 | `parent_unpublished` | Publish of a stay whose destination is not published, or a save that moves a published stay to an unpublished destination |
| 409 | `amenities_mismatch` | AR/ES `amenities` length differs from EN (the public build would fail, `stays.ts`) |
| 413 / 415 | `too_large` / `wrong_type` | Body size / content type |
| 503 | `unavailable` | Supabase settings missing or the database did not answer |

### 1.2 Shared value shapes

- **Locale** `"en" | "ar" | "es"`. **Status** `"published" | "draft"` (C-08; AR/ES from Translate are saved `draft`).
- **Save semantics (every `save`, every entity):** a key **absent** from `item` leaves that column or that set of join rows
  untouched; a key **present** (including `null` or `[]`) sets it. Join sets (`gallery_media_ids`, `connections`,
  `destination_ids`, `stay_ids`, `links`) are replaced only when their key is present. On create, absent keys take the
  database default. So a screen may send only the fields it shows.
- **Translations object** in every save: `translations: { "en": Text & { "status": Status }, "ar": … | null, "es": … | null }`.
  A locale **absent** = that record untouched; **null** = that record deleted; EN is required on create and can never be
  null. Text fields are trimmed; empty strings are stored as null for optional fields.
- In every detail response: `translations: { "en": Text & {status} | null, "ar": …, "es": … }` and
  `translation_state: { "en": "published"|"draft"|"missing", "ar": …, "es": … }`.
- **Money**: AED as a decimal **string** with at most 2 decimals, `"1250.00"`, both ways; `null` = not set. Never a float in
  a request. (Phase 4 converts to fils.)
- **Dates**: `"YYYY-MM-DD"`, calendar dates, UAE business meaning; no times.
- **MediaRef** (in responses): `{ "id": uuid, "key": "stays/x/hero.webp", "url": "https://media.almarprivatejourney.com/…", "width": 1600, "height": 1084, "alt_en": "…" }`.
- **slug**: `^[a-z0-9]+(-[a-z0-9]+)*$`, max 80, unique per table, never changes after publish (409 `invalid` with field `slug` if changed on a published row: public URLs depend on it).

### 2.4 Payloads and refusals as built (plan 03.2-01, additive; nothing above was renamed)

- **Item payloads** are exactly the `item` objects of §5 plus `id`. A key absent leaves the column or join set alone; `is_published` and
  `position` are never accepted by a save (use `ops_publish`, `ops_reorder`). A published row keeps its slug (`almar:invalid`, field `slug`).
  `ops_save_journey_tier` takes an existing `id` only (no create) and, besides `is_featured` / `media_id` / `translations`, the five
  columns the route parses from the English `price_label`: `price_from_amount`, `price_from_currency`, `est_low`, `est_high`,
  `est_open_ended` (each set only when its key is present).
- **Translations** inside a save: a language absent = untouched, `null` = deleted (never `en`), an object = upserted, and inside it a key
  absent = that field untouched. On create the English record is required (`almar:invalid`, field `translations.en`). Required text per
  record: `name` (`title` for stays; `name` and `price_label` for journeys); a blank one is `almar:invalid` with `field`
  `translations.<locale>.<name>`.
- **Money in, money out**: decimal strings or numbers in; `ops_get` / `ops_list` return money as `"1250.00"` strings (`base_nightly_rate_aed`,
  `pets_fee_aed`, `price_aed`). `MediaRef` carries `key`, never `url` (the route adds it with `mediaUrl()`).
- **`ops_save_stay_rate(p)`**: flat keys `{id?, stay_id, first_night, last_night, nightly_rate_aed}` (the route flattens `range`). An overlap raises
  SQLSTATE `23P01`, message `almar:rate_overlap`, detail `{"conflict_id": uuid|null}`.
- **`ops_save_stay_access(p)`**: `{stay_id, access: {address, wifi_name, wifi_password, door_code, notes}}` (the fields may also sit at the top level).
- **`ops_save_media(p)`**: `{key, width, height, bytes, content_type, sha256, alt_en}`; `alt_en` is required for a new row.
  **`ops_save_image_alts(p)`**: `{id, alt: {en?, ar?, es?}, status: {ar?, es?}}` (a language only in `status` changes that record's status; an
  alt set without a status is `published` for English and `draft` for Arabic and Spanish).
- **`ops_delete_media`** refuses an imported photo with SQLSTATE `23503`, message `almar:in_use` (detail `{"reason": "imported"}`): pages that stay in
  the fixtures (home, about, contact, blog) keep their photos by key and their alt text by image id, and the database cannot see them.
  `mapDbError` already maps 23503 to `in_use`.
- **`ops_publish`** codes: `parent_unpublished` (stay under an unpublished destination), `publish_incomplete` (any gap but amenities),
  `amenities_mismatch` (only the amenity lists differ in length), `has_published_stays` (unpublish of a destination). `missing` entries for
  a field that is not per language have `locale: null` (`hero_media_id`, `media_id`, `destination_ids`).
- **`ops_save_stay`** raises `almar:amenities_mismatch` for a language whose amenity list differs in length from English on every save of a
  published stay, and on a draft whenever that language already holds a non-empty list (an empty list is a draft in progress; `ops_publish` refuses it).
- `catalog_item_stays.position` counts from 0 inside the stay's own list per kind; `stay_gallery.position` counts from 1.
- `api_inclusions` columns: `inclusion_id, locale, status, label, position, slug`. `api_*` image objects are `json` (not `jsonb`) so their keys keep the
  fixture order.
- Internal helpers `catalog_*` exist (fail, invalid, txt, raw, blank, txt_array, uuid_array, need_media, entity_meta, save_translations, tr_json,
  tr_all, tr_state, gaps, media_ref, media_uses, media_live); like every function they are executable by `service_role` only. Later plans do not call them.

Business refusals inside RPCs are raised as `raise exception using errcode = 'P0001', message = 'almar:<code>', detail = <json text>`
(`almar:not_found`, `almar:published`, `almar:amenities_mismatch`, `almar:invalid`); `lib/ops/route.ts` `mapDbError` maps them,
plus 23505 → `slug_taken`, 23P01 → `rate_overlap`, 23503 → `in_use`. `ops_publish` does not raise for a refused publish: it
returns `{ ok: false, code, missing }`.

```ts
export function opsGet(handler: (ctx: { owner: OwnerContext; url: URL }) => Promise<Response | OpsResult>): (request: Request) => Promise<Response>;
export function opsPost<B>(parse: (body: unknown) => B /* throws OpsInvalid */, handler: (ctx: { owner: OwnerContext; body: B; request: Request }) => Promise<OpsResult>): (request: Request) => Promise<Response>;
// Raw body (03.2-09 upload): owner, then origin; no JSON parse, no 64 KiB cap (the handler enforces its own limits).
export function opsPut(handler: (ctx: { owner: OwnerContext; request: Request }) => Promise<OpsResult>): (request: Request) => Promise<Response>;
export type OpsResult = { status?: number; body: Record<string, unknown> & { ok: boolean } };
export class OpsInvalid extends Error { constructor(field: string, locale?: "en" | "ar" | "es"); }
export function mapDbError(error: { code?: string; message?: string; details?: string }): { status: number; code: string; detail?: unknown };
```

`requireOwner()` runs first, then the Origin check (POST/PUT), then size/type, then `parse`.

**Client types:** `components/ops/api-types.ts` is created by **03.2-11** (controller, 2026-10-05; Fable review of the kit)
and is the one place the response shapes of §5–6 are typed for the screens: `MediaRef`, `Locale3` (= §1.2 Locale),
`TextStatus` (= §1.2 Status), `TranslationState`, `OpsError` (the error envelope), every `*Summary` / `*Detail`,
`SiteStatus`. 03.2-04 imports from it and adds only what is missing; it never recreates the file or renames these.
Still open for 03.2-04/-13: `JourneyDetail.price_from` currency (typed `"USD" | "AED"` with `amount: Aed`) and a type for the
blocks `add` reply `overlapping_bookings` (§5.4). Screens import from it; nobody redefines `MediaRef`. 03.2-05 adds: when the
handler's body has `affects_site: true`, call `requestSiteUpdate(owner.admin)` and attach `site`.

## 5. Endpoints

### 5.1 Destinations — `/api/ops/destinations` (03.2-04)

`GET /api/ops/destinations` → `{ ok, items: DestinationSummary[] }` ordered by `position`.
`DestinationSummary = { id, slug, name_en, is_published, position, stay_count, published_stay_count, hero: MediaRef|null, translation_state, updated_at }`

`GET /api/ops/destinations?id=<uuid>` → `{ ok, item: DestinationDetail }`.
`DestinationDetail = { id, slug, is_published, position, hero_media_id, inset_media_id, hero: MediaRef|null, inset: MediaRef|null, translations: { en|ar|es: { name, short_line, region, summary, nights_label, status } | null }, translation_state, updated_at }`

`POST /api/ops/destinations`:
- `{ "action": "save", "item": { "id"?: uuid, "slug", "hero_media_id": uuid|null, "inset_media_id": uuid|null, "translations": {…} } }` → `{ ok, id, affects_site }` (`affects_site` = row is published)
- `{ "action": "delete", "id" }` → 409 `published` / `in_use` (has stays) or `{ ok, id, affects_site: false }`
- `{ "action": "reorder", "ids": [uuid, …] }` (all destination ids, new order) → `{ ok, affects_site }`

### 5.2 Stays — `/api/ops/stays` (03.2-04)

`GET` list → `StaySummary = { id, slug, title_en, destination_id, destination_name_en, is_published, position, base_nightly_rate_aed, bookable: boolean, hero: MediaRef|null, translation_state, updated_at }`. `bookable` = published and base rate set.
`GET ?id=` → `StayDetail = { id, slug, destination_id, is_published, position, max_guests, min_guests, bedrooms, bathrooms, min_nights, pets_rule, pets_fee_aed, infants_count, base_nightly_rate_aed /* read-only here */, hero_media_id, hero, gallery: MediaRef[] /* ordered */, experience_ids: uuid[], service_ids: uuid[], has_access: boolean, translations: { en|ar|es: StayText & {status} | null }, translation_state, updated_at }`
`StayText = { title, tagline, neighborhood, guests_label, bathrooms_label, beds_label, price_label, price_note, description: string[], amenities: string[], inclusions: string[], policy_headings: string[] }`

`POST /api/ops/stays`:
- `save`: `item = { id?, slug, destination_id, max_guests, min_guests, bedrooms, bathrooms, min_nights /* int ≥ 1, default 1 */, pets_rule: "allowed"|"not_allowed"|"fee"|null, pets_fee_aed: "…"|null /* required iff fee */, infants_count: boolean|null, hero_media_id, gallery_media_ids: uuid[] /* order = position */, translations, connections?: { experience_ids: uuid[], service_ids: uuid[] } }`. `connections` (when present) replaces this stay's `catalog_item_stays` rows in that order (kinds checked). AR/ES `amenities` must have the EN length (409 `amenities_mismatch`). Changing `destination_id` of a **published** stay to a destination that is not published → 409 `parent_unpublished` (the build would fail); moving between published destinations is allowed.
- `delete`, `reorder` as 5.1.

### 5.3 Rates — `/api/ops/stay-rates` (03.2-04) (`affects_site: false`: rates are never baked, C-04)

`GET ?stay_id=` → `{ ok, stay_id, base_nightly_rate_aed, ranges: [{ id, first_night, last_night, nights, nightly_rate_aed }] }` ordered by `first_night`.
`GET ?stay_id=&from=&to=` adds `nights: [{ night, nightly_rate_aed, source: "range"|"base"|null }]` (max 366 nights) from `stay_night_rates`.

`POST`:
- `{ "action": "set_base", "stay_id", "base_nightly_rate_aed": "1250.00" | null }`
- `{ "action": "save_range", "stay_id", "range": { "id"?, "first_night", "last_night", "nightly_rate_aed" } }` → 409 `rate_overlap` with `detail.conflict_id`; `last_night >= first_night`; at most 730 nights
- `{ "action": "delete_range", "id" }`

### 5.4 Availability blocks — `/api/ops/blocks` (03.2-04) (`affects_site: true`: blocked days are baked into the stay pages as hints)

`GET ?from=&to=[&stay_id=|&destination_id=]` (window ≤ 400 days) → `{ ok, blocks: [{ id, scope, destination_id, stay_id, starts_on, ends_on, reason, created_at }] }` (blocks overlapping the window; with `stay_id`, also the destination and all-scope blocks that cover it).
`POST`:
- `{ "action": "add", "block": { "scope": "all"|"destination"|"stay", "destination_id"?, "stay_id"?, "starts_on", "ends_on", "reason"? } }` → `{ ok, id, affects_site: true, overlapping_bookings }` (0 until Phase 4; the screen shows the D-87 warning when > 0)
- `{ "action": "delete", "id" }`

### 5.5 Stay access — `/api/ops/stay-access` (03.2-04) (`affects_site: false`, C-14)

`GET ?stay_id=` → `{ ok, stay_id, access: { address, wifi_name, wifi_password, door_code, notes, updated_at } | null }`
`POST { "action": "save", "stay_id", "access": { address, wifi_name, wifi_password, door_code, notes } }` (each ≤ 2,000 chars, null allowed). Never logged.

### 5.6 Experiences and services — `/api/ops/catalog` (03.2-04)

`GET [?kind=experience|service]` → `CatalogSummary = { id, slug, kind, unit, price_aed, is_uae, is_home_pickup, name_en, is_published, position, image: MediaRef|null, destination_ids, stay_count, translation_state, updated_at }`
`GET ?id=` → `CatalogDetail = { id, slug, kind, unit, price_aed, is_uae, is_home_pickup, media_id, image, destination_ids, stay_ids, is_published, position, translations: { en|ar|es: { name, summary, duration_label, status } | null }, translation_state, updated_at }`
`POST`:
- `save`: `item = { id?, slug, kind, unit, price_aed: "…"|null, is_uae, is_home_pickup /* true on a second item → 409 invalid field is_home_pickup (unique) */, media_id, destination_ids: uuid[], stay_ids: uuid[], translations }`. Stay links: kept pairs keep their position; new pairs go to the end of that stay's list; removed pairs are deleted.
- `delete`, `reorder` (ids of one `kind` or all).

### 5.7 Team — `/api/ops/team` (03.2-04)

`GET` → `TeamSummary = { id, slug, name_en, role_en, is_published, position, photo: MediaRef|null, translation_state, updated_at }`
`GET ?id=` → `TeamDetail = { id, slug, photo_media_id, photo, email, links: [{label, url}], is_published, position, translations: { en|ar|es: { name, role, bio, status } | null }, translation_state, updated_at }`
`POST`: `save` (`item = { id?, slug, photo_media_id, email: string|null, links: [{label ≤ 40, url https ≤ 300}] /* ≤ 8 */, translations }`), `delete`, `reorder`.

### 5.8 Journeys (Packages) — `/api/ops/journeys` (03.2-04)

`GET` → `JourneySummary = { id, slug, name_en, price_label_en, is_featured, is_published, position, image: MediaRef|null, translation_state, updated_at }`
`GET ?id=` → `JourneyDetail = { id, slug, is_featured, media_id, image, price_from: {amount, currency}|null, price_estimate: {low, high, currency: "AED", open_ended}|null, is_published, position, translations: { en|ar|es: { name, price_label, tagline, duration_label, ideal_for_label, ideal_for, body, status } | null }, translation_state, updated_at }`
`POST`:
- `save` (existing ids only; no create, no delete in v1, C-15): `item = { id, is_featured, media_id, translations }`. The server parses `price_from` / `price_estimate` from the EN `price_label` (`lib/ops/journey-price.ts`, the rule `tests/data-prices.test.mjs` pins); unparsable → both null. The label is stored verbatim.
- `reorder`. Show/hide = `/api/ops/publish`.

### 5.9 Publish — `/api/ops/publish` (03.2-04; 03.2-05 adds the rebuild)

`POST { "entity": "destination"|"stay"|"catalog_item"|"team_member"|"journey_tier", "id", "published": boolean }`
→ `{ ok: true, id, is_published, affects_site: true, warnings: [{ code: "no_base_rate" } | { code: "no_price" }] }`
or 409 `publish_incomplete` (`detail.missing`), `has_published_stays`, `parent_unpublished`, `amenities_mismatch`.

Publish rules (C-08 and the build's own checks). **Every text field filled in EN must also be filled in AR and ES**
(arrays: same length and no empty item); `missing` lists each gap as `{locale, field}`. The table adds the fields that are
required even in EN:

| Entity | Required in **each** of en, ar, es (beyond the rule above) | Also required | Warning (published anyway) |
|---|---|---|---|
| destination | `name` | `hero_media_id` | — |
| stay | `title` | `hero_media_id`; destination published; AR/ES `amenities` length = EN | `no_base_rate` (C-12: the card keeps its price label; not bookable) |
| catalog_item | `name` | `media_id` (ROADMAP SC2), ≥ 1 destination link | `no_price` (not offered as an add-on in Phase 4) |
| team_member | `name` | — | — |
| journey_tier | `name`, `price_label` | `media_id` | — |

Unpublish: always allowed, except a destination with published stays (`has_published_stays`).

### 5.10 Media — `/api/ops/media` (**route owned by 03.2-09**, RPCs in 03.2-01)

- `GET [?q=&limit=60&after=<key>]` → `{ ok, items: [{ id, key, url, width, height, content_type, source, alt: { en, ar, es }, alt_status: { en, ar, es }, used_by: number }], next: string|null }`
- `PUT` raw body: headers `Content-Type` in `image/webp|image/jpeg|image/png`, `Content-Length` ≤ 15 MB, `x-almar-sha256` (64 hex), `x-almar-width`, `x-almar-height` (1…10000), `x-almar-alt-en` (URI-encoded, required). Key `uploads/<first 32 hex>.<webp|jpg|png>`; `MEDIA.head` then `MEDIA.put(…, { sha256 })` only when absent; then `ops_save_media`. → `{ ok, id, key, url, created }`
- `GET` list reads `ops_list('media')`.
- `POST { "action": "save_alt", "id", "alt": { en, ar?, es? }, "status": { ar?, es? } }` → `ops_save_image_alts` → `{ ok, id, affects_site }`; `{ "action": "delete", "id" }` → `ops_delete_media` (R2 object kept).

### 5.11 Translate — `/api/ops/translate` (**owned by 03.2-10**)

`POST { "target": "ar"|"es", "fields": { "<name>": string | string[] } }` → `{ ok, target, fields }` (same keys, same array
lengths, nothing empty) | 429 `translate_limit` | 502 `translate_failed`. Nothing is saved; the screen saves AR/ES with
`status: "draft"`.

## 6. Site status — `/api/ops/site-status`, `/api/ops/site-update` (03.2-05)

`SiteStatus = { state: "up_to_date"|"updating"|"failed", requested_seq, live_seq, requested_at, built_at, last_hook_at, last_hook_result }`

- `GET /api/ops/site-status` → `{ ok, site: SiteStatus }`. Rules: up to date when `live_seq >= requested_seq`;
  updating when behind and `now − requested_at < 28 min` and the last hook call did not fail; else failed.
  `live_seq` comes from `GET https://almarprivatejourney.com/site-version.json` (no-store); a 404 counts as 0.
- `POST /api/ops/site-update` `{}` → fires the deploy hook again ("Try again"), `{ ok, site }`.
- Shown in the ops shell as one line: "Up to date · 14:05" / "Updating since 14:02" / "Update failed · 14:30 · Try again"
  (EN/AR/ES, pictures signed first, 03.2-05).
