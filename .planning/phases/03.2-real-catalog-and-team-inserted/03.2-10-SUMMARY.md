# 03.2-10 Summary: owner Translate button (Workers AI, Gemma 4 26B)

The owner types English and clicks one button. Arabic and Spanish come back as drafts in their tabs. Nothing is
saved and nothing is published by Translate: the screen's Save stores them with status draft, and they stay draft
until the owner ticks "I checked this translation".

## What was built

- **`lib/ops/translate-prompt.ts`**: `systemPrompt(target)`, `userMessage`, `schemaFor` and `checkSameShape`.
  - The prompt sets a luxury-travel register.
  - It keeps names unchanged: ALMAR, Getsemaní, Cartagena, Barú, Medellín, Bogotá, San Andrés, Cocora, Antioquia, Colombia.
  - Arabic is Modern Standard Arabic; Spanish is "Latin American Spanish, Colombian usage, formal usted".
- **`lib/ops/translate.ts`**:
  - `TRANSLATE_MODEL`, `translateFields(run, fields, target)`, `classifyAiError` and `parseTranslate`.
  - `parseTranslate` caps: target ar|es, 40 fields, 8,000 characters per field, 60 list items, at least one field with text, lowercase snake_case field names.
  - Request body:
    `{ messages, max_completion_tokens: min(8192, len+512), temperature: 0.2, response_format: { type: "json_schema", json_schema: { name, schema, strict: true } }, chat_template_kwargs: { enable_thinking: false } }`.
  - Replies are read from `choices[0].message.content`.
  - A reply in a code fence or prose is accepted only if it holds exactly one JSON object. Thinking text means failed.
- **`lib/ops/translate-route.ts`**: the only place that reaches `getCloudflareContext().env.AI.run`.
  - Without the binding (dev server, other Workers) the route answers 502 `translate_failed`.
  - Deviation: the plan put this call in `route.ts`, but the existing route guard (`tests/ops-route.test.mjs`) lets an ops route import only `lib/ops/*`.
- **`app/api/ops/translate/route.ts`**: `opsPost`, so the owner check and the Origin check come first. It sets `dynamic = "force-dynamic"`. Nothing is saved and no field text is logged.
- **`components/ops/translate-button.tsx`**:
  - Sends two `opsSend` calls in parallel (`Promise.allSettled`) and contains no `fetch(`.
  - Asks before replacing existing AR/ES text.
  - Calls `onDrafts` once for each target that succeeds and says which target failed.
  - The status line is `role="status"`.
  - It drops the answers if the English changed during the request or the button unmounted. Busy always ends.
- **Copy** (`lib/copy/ops-translate.ts`): EN, AR and ES with the same keys. ES uses usted.
- **Error classes**: `classifyAiError` returns "limit" only for status or code 429, or a message matching `/daily|neurons?/i`. Everything else is "failed".

## Deviations

1. The binding call lives in `lib/ops/translate-route.ts`, not `route.ts`, because of the route import guard.
2. ES pictures were shot as well, on the owner's EN/AR/ES rule: 72 pictures, not 48.
3. The pictures block is gated by `OPS_TRANSLATE_PICTURES=1`, the same way as ops-kit, so the normal suite doesn't rewrite signed pictures.
4. Task 2 was written code first, then tests. There is no separate failing-test commit.
5. Fixes from the review (Sonnet, fresh context), each committed:
   - the built-Worker route list now has ten routes;
   - a bare "limit" error no longer shows the daily-limit line;
   - answers are dropped when the English changes during the request;
   - all-empty fields get 400;
   - a note that field names are snake_case.
