## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug in the plan] `/auth/confirm` is a page, not a route handler**
- **Found during:** Task 2 (the ops build stopped: `/auth/confirm/route is missing from the build`)
- **Issue:** the plan, its behaviour example and its precondition name `app/auth/confirm/route.ts`; the tree has `app/auth/confirm/page.tsx` (the Continue screen), manifest key `/auth/confirm/page`.
- **Fix:** `opsPathsFrom` requires each OPS_AUTH_PATHS entry as `<path>/route` or `<path>/page`; `/api/health` stays required as a route. Tests use the real key and cover both forms.
- **Files:** `lib/ops-routes.ts`, `tests/ops-runtime.test.mjs` - **Commit:** `46017e6`

**2. [Rule 1 - Bug] The marketing `_redirects` shipped inside `out-ops/`**
- **Found during:** Task 2, probing the built Worker (`/services` answered 301 on the ops host)
- **Fix:** `assembleOut({ pages: false })` removes `_redirects` after copying `public/`; a test and the spec (`/services` is the branded 404) pin it. The public folder keeps its redirects.
- **Files:** `scripts/assemble-cloudflare.mjs`, `tests/ops-runtime.test.mjs`, `tests/build/ops-runtime.spec.ts` - **Commit:** `46017e6`

**3. [Rule 1 - Bug in the plan's runbook] Step 1 said to export the NEXT_PUBLIC Supabase names in the build shell**
- `assertNoPublicEnv` (job 10) stops the build for any `NEXT_PUBLIC_*` in the shell, and job 02's hand-over says they are "never in the build shell". The runbook instead requires `env | grep -c '^NEXT_PUBLIC'` = 0 and puts the three Supabase names (`NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY`) plus `RESEND_API_KEY` on `almar-ops` as Worker secrets. **Commit:** `ed970a9`

**4. [Rule 3 - Blocking] The Playwright readiness poll got a 500 from the ops Worker**
- Playwright polls `GET /` with host `127.0.0.1` (not the ops host); on `almar-ops` that is the marketing home, which this Worker does not hold. Fix: optional `PW_READY_PATH` in `playwright.build.config.ts` (default `/`, so every existing run is unchanged); the ops run uses `/api/health`. The plan allowed a small additive change here. **Commit:** `46017e6`

### Stricter than the plan (small, all pinned by tests)

- `opsPathsFrom` also refuses `app/api/ops/route.ts`, a section named `api`, `auth`, `dashboard`, `cdn-cgi` or starting with `_`, and (like job 10 for `/api`) a grouped segment under `/api/ops`; it requires the `/api/health` route.
- `serverPathsFrom` skips `/api/ops/*` **after** its shape checks, so the public build still refuses a dynamic or page `/api/ops` entry.
- `assertOpsPath(path, all?)` has the optional second argument for the "twin" rule (a bare `/<section>` needs `/dashboard/<section>`), the only way to tell `/about` from a section by shape.
- `isLiveOpsPath` accepts both the browser path and the rewrite target (`/dashboard/<section>`): if Next re-runs middleware on a rewrite, the answer is the same.

### Not done on purpose

- `OPS_HOST_LIVE` in `lib/host.ts` is still `false` (job 02's test pins it). Flipping it makes the public site offer the dashboard handoff; it is a separate controller step after the runbook's checks (runbook section 7).
